 Begin Scanning a Bitbucket App 

 Authorize Data Security to connect to Bitbucket to scan all content shared
 within the app. 

 Where Can I Use This? What Do I Need? 

 Strata Cloud Manager 

 Data Security license 

 Or any of the following licenses that include the Data Security license: 

 CASB-X 

 CASB-PA 

 To connect a Bitbucket app and begin scanning assets, you need to: 

 Ensure that you have a Bitbucket Site administrator account. 

 Grant Data Security access to Bitbucket. 

 Add the Bitbucket app to Data Security , providing Data Security information
 about your Bitbucket workspace and account. 

 If you onboarded your Bitbucket app before May 20, 2022, there is a newly published app
 available on the Bitbucket Marketplace. To replace your existing app, you must
 delete it from the dashboard, uninstall (Workspace > Settings > Installed apps >
 Remove), and onboard the app again. If you don’t, some new features won't be
 available, including remediation and user activity monitoring capabilities. Your
 existing app does not support remediation, so you likely did not create any policy
 rules that are purged when you delete the app. After you onboard again, you can
 create policy rules for improved data loss prevention. 

 Support for automated remediation capabilities varies by SaaS application.

 Bitbucket Onboarding Time 

 Data Security scans for two Bitbucket asset types: 

 Commits —Repository commits across all branches. 

 Repository —Repository assets are scanned when the first commit
occurs or when exposure settings are changed. The Owner name mentioned
in the Assets page is the last person who edited the repository settings. 

 When you perform Change Sharing, the repository asset is updated with Exposure as “Internal”,
 and the Workspace name is displayed as the Owner. 

 The specific assets that Data Security scans and displays
in the SaaS Security web interface are based on your onboarding
time , which begins when you initiate scanning : 

 Post-onboarding —Commits and Repository updates after onboarding
are scanned. 

 Pre-onboarding —Commits and Repository updates before onboarding
are not scanned. Only newly added content to pre-onboarding commits
is scanned. 

 Add Bitbucket App 

 In order for Data Security to scan assets, you must consent to specific permissions when
 adding the Bitbucket app. 

 ( Recommended ) Add your Bitbucket domain as an internal domain . 

 Log in to 
 Strata Cloud Manager . 

 Select Configuration SaaS Security Data Security Applications Add Application Bitbucket . 

 Click Add New to open the Connect Bitbucket to
 Data Security page. 

 In the Prepare to install Bitbucket app section, ensure that you
 have a Bitbucket workspace admin account. 

 In the Install SaaS Security in Bitbucket section, select Go to
 Forge UI app . 

 You are redirected to the Atlassian developer console to install the
 Forge App. 

 Click Get app . 

 Select the workspace where you want to install the app and
 Install . 

 After installing the Forge App, wait for up to 5
 minutes before entering your Workspace UUID to connect and
 onboard. 

 Go to your Bitbucket Repository Settings page and
 copy the workspace UUID (including the curly braces if present). Keep it
 handy for onboarding later. 

 Return to the onboarding steps and enter your Bitbucket workspace UUID and
 Connect . 

 A sample screenshot of a successful onboarding is shown below: 

 ( Optional ) If you need to reauthenticate your Bitbucket instance,
 you have to uninstall and reinstall the Forge app. To uninstall the Forge
 app: 

 Log in to Bitbucket and open the target workspace. 

 Select Workspace Settings Apps and Features Installed Apps . 

 Scroll down and locate the Forge app you want to remove (for
 example, Palo_Alto_Networks_CASB_STG_Bitbucket). 

 Uninstall the app.

 Identify Risks 

 When you add a new cloud app, then enable scanning ,
 Data Security automatically scans the cloud app against the
default data patterns and displays the match occurrences. You can
take action now to improve your scan results and identify risks. 

 To start scanning the new Bitbucket app for risks, select Configuration SaaS Security Data Security Applications Bitbucket View Settings ... Start Scanning . 

 Monitor the scan
results . 

 During the discovery phase, as Data Security scans
files and matches them against enabled policy rules: 

 Verify that Data Security displays assets. 

 Verify that your default policy rules are effective. If the results don’t capture all the risks
 or you see false positives, proceed to the next step to improve
 your results. 

 ( Optional ) Modify match criteria for existing
 policy rules. 

 ( Optional ) Add new policy rules. 

 Consider the business use of your cloud app, then identify
risks unique to your enterprise. As necessary, add new: 

 asset rules 

 user activity rules 

 ( Optional ) Configure or edit a data pattern. 

 You can Configure Data Patterns to
 identify specific strings of text, characters, words, or patterns to
 make it possible to find all instances of text that match a data pattern
 you specify.

 FAQs for Bitbucket App 

 The most common questions related to onboarding a Bitbucket app are as follows: 

 Question 

 Answer 

 What if there are multiple files in a commit? 

 Each commit is treated as a separate asset. 

 Are merge commits scanned? 

 To avoid duplicates, merge commits are not
scanned. 

 What if a commit is associated with multiple branches? 

 Data Security does not scan the same
commit twice. If a commit is part of multiple branches, only the
first commit is scanned. 

 How are assets named for commits? 

 The asset name is a combination of the short Commit ID and filename. 

 What does the Repository on the Asset Details
(Basic Info) page hyperlink to? 

 Directs you to the parent repository asset, not the repository on Bitbucket.
