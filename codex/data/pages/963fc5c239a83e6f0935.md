# Persistence Mechanism Instruction

Persistence Mechanism Instruction

Severity

🟡 Medium (6)

Short Description

Flags AI extensions that instruct the agent to create persistent side effects — modifying configuration, installing packages, writing to startup files, or creating cron jobs.

Suggestion

Confirm that persistence matches the component's purpose — setup and installer components legitimately need it. Where it does not, treat writes to startup files and scheduled jobs as high-priority: those survive uninstalling the component.

Information

Most agent actions end with the session. Persistence instructions are the ones that do not: package installations, configuration edits, shell profile modifications, scheduled jobs, and startup entries all outlive the conversation that created them.

Environment setup skills and installer commands are supposed to do this. What separates routine persistence from a concern is what the change is and where it lives: installing a documented dependency is ordinary, while adding a line to a shell profile or registering a cron job establishes a foothold that runs independently of the agent, on every login or on a schedule. Plan for the fact that removing the component does not undo those effects — they persist until someone finds and removes them directly.

Risks

Survives removal: Startup entries and scheduled jobs keep running after the component is uninstalled.

Independent execution: Cron jobs and login scripts run outside the agent, without any agent or user involvement.

Supply-chain reach: Instructed package installations pull in dependencies that were never reviewed.

Configuration drift: Accumulated changes across sessions leave the environment in a state nobody deliberately configured.

Recommended Actions

Investigate the component

Read the evidence to identify what persists and where it is written.

Prioritize startup files, cron jobs, and scheduled tasks over ordinary configuration edits.

Confirm that persistence is documented and matches the component's stated purpose.

Contain and remediate

Inventory affected devices for the specific artifacts named in the evidence.

Remove the persistent artifacts explicitly — uninstalling the component will not do it.

Review any packages the component installed and their dependencies.

Remove the component if the persistence is undocumented or unnecessary.
