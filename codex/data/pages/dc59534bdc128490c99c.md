 Onboard an IDrive App to SSPM 

 Connect an IDrive instance to SSPM to detect posture risks. 

 Where Can I Use This? What Do I Need? 

 Strata Cloud Manager 

 SaaS Security Posture Management license 

 Or any of the following licenses that include the Data Security license: 

 CASB-X 

 CASB-PA 

 For SSPM to detect posture risks in your IDrive instance, you must onboard your IDrive
 instance to SSPM. Through the onboarding process, SSPM logs in to IDrive using
 administrator account credentials. SSPM uses this account to scan your IDrive
 instance for misconfigured settings. If there are misconfigured settings, SSPM
 suggests a remediation action based on best practices. 

 SSPM gets access to your IDrive instance by using Okta SSO or Microsoft Azure credentials that
 you provide during the onboarding process. For this reason, your organization must
 be using Okta or Microsoft Azure as an identity provider. The Okta or Microsoft
 Azure account must be configured for multi-factor authentication (MFA) using
 one-time passcodes. 

 To onboard your IDrive instance, you complete the following actions: 

 Collect information for accessing your IDrive instance. 

 To access your IDrive instance, SSPM requires the following information,
 which you will specify during the onboarding process. 

 Item Description 

 User email The login email address of an administrator
 account that SSPM will use to access your IDrive instance.

 ( Required Permissions ) The user must be
 an IDrive administrator. 

 Password The password for the login account. 

 If you're logging in through Okta, you must provide SSPM with the following
 additional information: 

 Item Description 

 Okta subdomain The Okta subdomain for your organization. The subdomain
 was included in the login URL that Okta assigned to your
 organization. 

 Okta 2FA secret A key that is used to generate one-time passcodes for
 MFA. 

 If you're using Azure Active Directory (AD) as your identity provider, you
 must provide SSPM with the following additional information: 

 Item Description 

 Azure 2FA secret A key that is used to generate one-time passcodes for
 MFA. 

 As you complete the following steps, make note of the values of the items
 described in the preceding tables. You will need to enter these values
 during onboarding to access your IDrive instance from SSPM. 

 Identify the Okta user account that SSPM will use to access your IDrive
 instance. 

 Required Permissions: The user account must have
 administrator privileges in IDrive. 

 Get a secret key for MFA. 

 The steps you follow to get the MFA secret key differs depending on
 the identity provider you're using to access the account. 

 ( For Okta log in ) To access the account
 through Okta : 
 Identify
 your Okta subdomain . 

 Generate and
 copy an MFA secret key . 

 ( For Microsoft Azure log in ) To access the account
 through Microsoft Azure : 
 Enable
 third-party software OATH tokens for the
 administrator account . 

 Configure
 the account for MFA and copy the MFA secret
 key . 

 Connect SSPM to your IDrive instance. 

 By adding an IDrive app in SSPM, you enable SSPM to connect to your IDrive
 instance. 

 Log in to 
 Strata Cloud Manager . 

 Select Configuration SaaS Security Posture Security Applications Add Application and click the IDrive tile. 

 On the Posture Security tab, Add
 New instance. 

 Specify how you want SSPM to connect to your IDrive instance. SSPM can
 Log in with Okta or Log in with Azure . 

 When prompted, provide SSPM with the login credentials and the
 information it needs for MFA. 

 Connect .
