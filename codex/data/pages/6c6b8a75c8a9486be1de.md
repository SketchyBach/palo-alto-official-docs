 Migrate from Cortex XSOAR 6 to Cortex XSOAR 8 SaaS (Self-Service) 

 Migrate from Cortex XSOAR 6 On-prem to XSOAR 8 SaaS 

 Use this procedure to migrate manually from Cortex XSOAR 6 On-Prem to Cortex XSOAR 8 SaaS. 

 Important 

 This procedure does not migrate incident and indicator data. Some Cortex XSOAR integrations and API endpoints support syncing data between Cortex XSOAR deployments. For more information, contact Customer Success or the Professional Services team. 

 The Cortex XSOAR 8 tenant is available for activation in Cortex Gateway. A CSP Super User is needed to see the tenant available for activation and to activate it.

 Task 2. Configure content 

 If using a development tenant, we recommend configuring this tenant first, as you install and configure content on the development tenant. 

 Familiarize yourself with user management in Cortex XSOAR 8, as it differs from Cortex XSOAR 6. 

 Identify the roles you have defined in Cortex XSOAR 6. 

 Recreate the roles in Cortex XSOAR 8 with the same permissions you have for each role on Cortex XSOAR 6 (if the role is not already present in Cortex XSOAR 8). 

 If you have nested roles in Cortex XSOAR 6, create user groups in Cortex XSOAR 8 to replicate the nested roles in Cortex XSOAR 6. The nested direction is reversed in Cortex XSOAR 8. For more information about user groups, see User group management . 

 Install and configure Marketplace content. 

 Note 

 In a development/production environment, you can only install Marketplace content on the development tenant. 

 In Cortex XSOAR 8, install the content packs used in Cortex XSOAR 6. After installation, configure each Cortex XSOAR 8 integration instance. Verify mappers and classifiers are set correctly for each instance. 

 Note 

 Some integrations are configured differently for Cortex XSOAR 8. For further information about the integration configuration changes, see Reconfigure integrations . 

 If you have integration instances in Cortex XSOAR 6 that connect to internal resources, and those resources cannot be reached by Cortex XSOAR 8 due to firewalls or other limitations, deploy engines to act as connectors between your internal endpoint accessed by the integration and Cortex XSOAR 8. For more information about engines, see Set up an engine . 

 Verify all integrations work in Cortex XSOAR 8. 

 If you have been using RBAC in Cortex XSOAR 6 for integrations/integration commands, configure the same RBAC settings for Cortex XSOAR 8. For more information, see Configure integration permissions . 

 Move custom content from Cortex XSOAR 6 to Cortex XSOAR 8. 

 Note 

 If using a development tenant, this step needs to be done on the development tenant. 

 In Cortex XSOAR 6, export your custom content. 

 Go to Settings → About → Troubleshooting , scroll down until you see the Custom Content section, and click Export . 

 In Cortex XSOAR 8, upload your custom content. 

 Go to Settings & Info → Settings → System → Server Settings . In the Custom Content section, drag and drop the exported file. 

 Create API keys in Cortex XSOAR 8 and update third-party services. For more information, see API Keys in Cortex XSOAR 8 . 

 Configure jobs in Cortex XSOAR 8 to match how they are set up in Cortex XSOAR 6. 

 Task 3. Perform validation testing 

 Perform validation testing on each tenant. It doesn't matter in which order you do this. 

 If using a development/production environment, ensure you can push and pull content between tenants. For more information, see Push content from a development tenant . 

 Temporarily enable incident fetching in your Cortex XSOAR 8 integration instances. 

 Note 

 If your Cortex XSOAR 6 production server is also fetching at the same time, this will fetch the same incidents into both platforms. 

 After incidents are fetched into Cortex XSOAR 8, verify that all playbooks execute correctly, that they run through to completion, and that all automations work. 

 After testing, disable incident fetching in your Cortex XSOAR 8 integration instances. 

 Verify that all jobs run correctly. 

 Verify that all scripts work. 

 If you are using External Dynamic Lists, confirm you have configured the Generic Export Indicators integration. In Cortex XSOAR 8, the Generic Export Indicators integration requires a username and password. For more information about the Generic Export Indicators integration, see Export Indicators . 

 Confirm that API triggers work if you use the API to ingest incidents. 

 Task 4. Set up access to Cortex XSOAR 8 for additional users 

 If you are not using SSO, add all users to the CSP portal to grant users access to the Cortex XSOAR 8 tenant. 

 If you are using SSO, configure SSO in your Cortex XSOAR 8 tenant and your identity provider. For more information, see Authenticate users using SSO . 

 After user access has been set up, verify that users can log into Cortex XSOAR 8. 

 Verify RBAC functionality works correctly. 

 Task 5. Post Migration Steps 

 Enable fetching in all of your integration instances. 

 In a development/production environment, push, pull, and install content on the production machine. For more information, see Install Content on a Production Tenant . 

 Disable activity on Cortex XSOAR 6: 

 Disable all jobs 

 In your integration instances, disable fetching incidents. 

 Wait for all playbooks to finish and for all open incidents to complete. 

 Disable all enabled integration instances. 

 Cortex XSOAR 8 can now be used as your working environment. 

 Note 

 Any third-party services that need to access Cortex XSOAR 8 must be updated with the new API and EDL information.
