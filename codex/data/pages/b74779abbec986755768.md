 Configure the Prisma Agent (Coexistence Tenant) 

 To manage both the Prisma Agent and GlobalProtect app on the same Prisma Access tenant (instance), you can onboard the Prisma Agent using a
 tenant that is configured for GlobalProtect.

 The settings for both the GlobalProtect app and Prisma Agent can coexist on
 the same Prisma Access or NGFW tenant (instance). 

 After you have configured the GlobalProtect app on a tenant and want to deploy the Prisma Agent to your mobile users, you can onboard the Prisma Agent on the same tenant. 

 By onboarding the Prisma Agent on an existing GlobalProtect-enabled tenant,
 you can reduce the operational overhead for managing separate tenants and
 configurations, such as creating backend resources like service connections and remote
 networks on each tenant. 

 Because the Prisma Agent and GlobalProtect app can be installed on the same
 endpoint, you can deploy both apps from the same tenant, reducing the effort for
 maintaining two separate tenants. If needed, your end users switch between the Prisma Agent and
 GlobalProtect app . This enables a seamless migration from the GlobalProtect
 app to the Prisma Agent . 

 Before you begin, ensure that you: 

 Contact your Palo Alto Networks account representative to activate the feature for
 the Prisma Agent and GlobalProtect coexistence-enabled tenant. 

 Contact your Palo Alto Networks account representative to activate the Prisma Agent feature. 

 Obtain the required licenses ( Prisma Access license for mobile users and a Strata Logging Service license with proper firewall storage space). If mobile
 users will be connecting to other connected networks, you will need either the Zero
 Trust Network Access or Enterprise Edition Prisma Access license that will
 provide the corporate access node (CAN) necessary to connect. 

 Activate Strata Cloud Manager Managed Prisma
 Access and set up Strata Cloud Manager Managed Prisma
 Access . 

 Ensure that your Prisma Access deployment is running at the minimum required
 Prisma Access dataplane version (10.2.10 or 11.2.0 and
 later). 

 Configure at least one authentication profile on the tenant. 

 Configure GlobalProtect , including the
 GlobalProtect portal .

 Prisma Agent and GlobalProtect Coexistence Considerations 

 Review the following considerations for the coexistence of the Prisma Agent and GlobalProtect on the same Prisma Access 
 tenant: 

 Coexistence is supported on both new Prisma Access deployments and existing
 deployments, as long as you upgrade the tenant to the required Prisma Access 
 dataplane version. 

 Support for the Prisma Agent on Prisma Access Insights is not
 yet available. 

 The Dynamic Privilege Access is not
 supported on a GlobalProtect-enabled tenant. 

 The agent infrastructure settings include the configurations for both the Prisma Agent domain name and the GlobalProtect portal name. 

 For user authentication, the Prisma Agent supports SAML
 authentication with Cloud Identity Engine and can coexist with GlobalProtect
 running with any of the existing authentication methods for GlobalProtect. 

 The allowlist ( Users Allowed to Authenticate ) in the Prisma Access authentication profile for the Prisma Agent ( Identity Services Authentication Authentication Profile ) must match the allowlist for GlobalProtect. 

 Gateway selection: 
 Both Prisma Agent and GlobalProtect can connect to
 on-premises and Prisma Access Mobile User (MU) gateways. 

 For a deployment that uses the authentication override certificate, Prisma Agent users can connect to on-premises NGFW
 gateways, as long as you export the authentication
 override certificate . 

 Endpoint considerations: 
 To have the GlobalProtect app automatically disabled when installing Prisma Agent , you can configure the agent deployment 
 by using the unload_gp option. 

 If your users also need to use the GlobalProtect app, they can switch between the Prisma Agent and GlobalProtect app . Contact your Palo Alto Networks
 account representative to enable this feature.
