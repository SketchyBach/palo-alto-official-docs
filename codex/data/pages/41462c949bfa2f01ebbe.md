# Access Sensitive Resources Instruction

For the complete documentation index, see llms.txt. This page is also available as Markdown.

Access Sensitive Resources Instruction

Severity

🟡 Medium (5)

Short Description

Flags AI extensions that instruct the agent to access or modify sensitive resources such as private keys, .env files, credentials, SSH keys, or system configuration.

Suggestion

Determine whether the component needs the resources it asks for. Reading .env to run a local server is reasonable; reading SSH keys rarely is. Check whether the access is paired with any outbound network activity.

Information

This finding covers instructions to read or modify sensitive local resources: .env files, private keys, SSH keys, credential stores, keychains, and system configuration. It is about access, not transmission — the component asks the agent to touch these resources, and the evidence shows which ones.

Legitimate uses are common — local development workflows read .env files, deployment helpers read cloud credentials — so for those this is a scoping check: does the component need exactly these resources, or more than its purpose requires? The important follow-up is where the data goes. Access alone keeps sensitive material on the machine; access combined with an exfiltration finding is a credential theft chain, and the two should be assessed together rather than separately.

Risks

Credential material in context: Secrets read into the agent's context can surface in later output or be retained by the model provider.

Over-broad access: A component may request more resources than its stated purpose justifies.

Modification risk: Instructions that write to system configuration or key files can break authentication or weaken host security.

Chain with exfiltration: Paired with an outbound data flow, access becomes theft.

Recommended Actions

Investigate the component

Read the evidence to identify the exact resources and whether access is read or write.

Compare the requested resources against what the component's purpose requires.

Check for co-occurring data exfiltration or code execution findings.

Contain and remediate

Restrict the agent's filesystem permissions to exclude key and credential paths.

Keep confirmation prompts enabled for sensitive file access.

Rotate credentials if the evidence shows access to key material and the component is untrusted.

Remove the component if the access is broader than its purpose requires.
