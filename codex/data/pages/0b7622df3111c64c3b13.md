 Task 2. Deploy your virtual machine on KVM 

 Deploy a virtual machine on KVM for Cortex XSOAR 8.14 On-prem. 

 The following is an example of deploying your VM on KVM from a QCOW2 image using virt-manager. 

 If you set your Cortex XSOAR environment as a standalone (single node), you cannot add nodes to it and switch to a cluster. If you deploy three nodes, you can later add nodes and expand the cluster. For more information, see Manage nodes in a cluster . 

 To implement built-in High Availability, deploy a cluster with three nodes (VMs), with each VM on a different hypervisor. This ensures that if one hypervisor fails, the other VMs continue to operate. 

 You then need to: 

 Establish trust between all nodes in the cluster (Task 6). 

 Set the Cluster FQDN to the either the virtual IP address or to the reverse proxy/ingress controller IP address (Task 7). The virtual IP or the reverse proxy/ingress controller serves as a single entry point to distribute traffic across the nodes in the cluster. 

 To use backup and restore functionality, deploy a second cluster in a secondary data center. For more information, see How to back up and restore Cortex XSOAR . 

 Copy the downloaded image file into your hypervisor. 

 For example, in the remote desktop CLI, run the following command to copy the source disk file to create a disk image for each VM, where opp1-deploy-disk.qcow2 is the name for the deploy disk you will use for your VM. 

 sudo cp /downloads/<file_disk_name>.qcow2 /mnt/opp-disk/disks/opp1-deploy-disk.qcow2 

 Copy the file to a mounted directory that is an SSD disk mount. 

 In your remote desktop, open the virt-manager application either by selecting System Tools → Virtual Machine Manager or by running the CLI command virt-manager --connect qemu+ssh://<user>@<host-ip>/system <VM-Name> 

 Click to create a new machine and select Import existing disk image. 

 Specify the path to the disk image file you created in Step 1 (for example, /mnt/opp-disk/disks/opp1-deploy-disk.qcow2 ) and select Debian 12 as the Operating System for the VM. 

 Set the memory and CPUs according to your preferred scale size. For example, for extra small scale, set Memory to 32768 MiB (32 GB) and CPUs to 16. 

 Give the VM a name and select Customize configuration before install. 

 Click finish. The customization menu opens. 

 Under Virtual Disk, set the Disk bus to SCSI. 

 For the disk to be recognized as an SSD, this must be set to SCSI. 

 Add a data disk to the VM. 

 Click Add Hardware. 

 In the Add New Virtual Hardware pane, select Storage and set Bus type to SCSI. 

 Click Manage..., and in the Locate or create storage volume pane select pool. Locate your storage pool, which should be linked to your mounted SSD disk. 

 If a storage pool does not exist (new VM), add one. 

 How to add a storage pool 

 Select the green + under the pool list. 

 Set the pool name and set the Type to dir: Filesystem Directory . 

 Set the Target Path to point to the mounted SSD disk directory. 

 Create a new volume. 

 Select the green + for the Volumes list. 

 Give the secondary disk a name (for example opp1-secondary-disk ) and set the Format to qcow2. 

 Set the required data disk size (for example, 775 GiB) and click Finish. 

 Select the volume you just created. 

 Add the required SCSI controller hardware. 

 Click Add Hardware. 

 Select Controller and set the Type to SCSI and the Model to VirtIO SCSI. 

 This controller will appear in the hardware list as Controller VirtIO SCSI 0 . 

 For both the boot disk and the data disk, configure the advanced settings to ensure they are recognized as an SSD. 

 Select the disk (for example SCSI Disk 1 or SCSI Disk 2). 

 Under Advanced options, set the Discard mode to unmap. 

 Set the Cache mode to your preferred mode (default is writethrough). 

 Click Apply. 

 Edit the XML configuration for both disks for them to be recognized as SSD. 

 For each disk (boot and data), select the XML tab. 

 Add the attribute rotation_rate with the value of "1" inside the <target> tag. 

 For example: <target dev="sdb" bus="scsi" rotation_rate="1"/> 

 Click Apply to save the XML changes. 

 Click Begin Installation to start the VM. 

 If the VM starts successfully, you should see the SeaBIOS and GRUB loading screen. If an error occurs, you will need to close the window, delete the machine and both volumes created, and restart the VM creation process. 

 Repeat from Step 1 for each additional virtual machine in the cluster. 

 Each virtual machine (VM) must have its own unique boot disk file. Copy the disk image file (.qcow2) from the /downloads folder to each target machine's mount point ( /mnt/opp-disk/disks/ ) and give it a unique name (for example, opp1-deploy-disk.qcow2 , opp2-deploy-disk.qcow2 , and opp3-deploy-disk.qcow2 ). 

 For first time login, the default user name and password is admin . 

 If you log in from the web console, you are prompted for your username and password. 

 If you log in from an external terminal, use the ssh admin@<server ip address> command to SSH log in. 

 Give the admin a new password as follows. 

 Save the SSH password securely. If you lose this password you cannot recover or change it, and to use SSH you will need to redeploy the cluster. 

 The password must be at least eight characters long and contain at least: 

 One lower case letter 

 One upper case letter 

 One number, or one of the following special characters: !@#% 

 If this is not a first time login, you can log in from the web console or from a terminal using the ssh admin@<server ip address> command to SSH log in. 

 The textual UI menu opens with all the configuration and installation options. 

 To start using the textual UI, click anywhere on the screen. 

 To navigate between the menu items, use the up and down arrow keys. To select a menu item, press the Enter key. 

 To navigate between fields within a menu item, use the Tab key. To save settings, tab to the Save button and press the Enter key. 

 To go back to the menu from a specific menu item field, press the esc key.
