 Prisma AIRS AI Runtime Firewall Prerequisites and Limitations 

 Prisma AI Runtime Security (AIRS) integrates with Anthropic Inference Hooks to
 inspect and govern every Claude prompt before it reaches the model. When a governed
 prompt arrives, Anthropic pauses inference, POSTs the conversation transcript to a
 Prisma AIRS endpoint, and enforces the `allow` or `deny` verdict AIRS returns—all
 before the model ever reads the message. 

 This
 feature reveres the normal call direction (i.e., Anthropic calls Prisma
 AIRS). 

 This page covers how the integration works, how to configure it, what data flows
 between the systems, and operational considerations. 

 This
 feature is limited to the U.S region only. 

 Prerequisites 

 Before configuring the integration: 
 The AIRS webhook endpoint is publicly reachable on HTTPS port 443 with a
 publicly-trusted certificate. Anthropic does not follow redirects. 

 Source IP allowlist (if applicable). Anthropic sends webhook requests from
 160.79.106.0/25. If your environment restricts inbound sources, allowlist
 this range. 

 IP allowlisting
 narrows exposure but is not a substitute for signature
 verification. 

 A configured AIRS scan profile Ensure that a configured AIRS API Key is
 linked to a configured AIRS scan profile. 

 Lightweight profiles (prompt
 injection, topic guardrails) are recommended for latency-sensitive gating; heavy
 profiles (DLP, malicious-code detection) add latency 

 Setup and Configuration 

 Enable the integration in AIRS. Log into Strata Cloud Manager (SCM) . In Prisma AIRS AIRS
 management UI, navigate to the Anthropic Inference Hooks configuration
 option. Click AI Security > AI Runtime > API Applications : 

 You can configure inference hooks
 using options for API Applications, AI Sessions, or API
 Violations. 

 Click Manage in the upper right portion of
 the AI Applications page: 

 Select Applications : 

 Click Add New Application/API Key : 

 Use Edit to
 configure an existing deployment profile. 

 In the Onboard API Account , select the profile to
 begin API onboarding, then click Next : 

 In the Add Application (Agent) screen, specify the
 following: 

 Include an Application Name . 

 Use the drop-down to select a Cloud
 Provider . 

 Select the Environment . 

 Select the AI Agent Framework . 

 Enter a Webhook Secret . 

 Use the toggle to enable the Security
 Profile ; use the drop-down to link an existing
 security profile or choose which profile to use in your app
 code. 

 Click Next . 

 In the Input API Details page: 

 Enter a name API Key Name . 

 Use the drop-down to select the key
 Rotation . 

 Click Generate API Key . 

 The Implement API Key screen appears, with
 the generated API key: 

 Click Done . 
 Next, you'll configure Anthropic Inference Hooks. 

 In the Anthropic console under Organization settings › Inference
 hooks : 

 Set the endpoint URL to the AIRS webhook URL
 ( https://service.api.aisecurity.paloaltonetworks.com/inference-hooks/scan/sync/request )
 provided in the Prisma AIRS console. 

 Add a custom header carrying your AIRS API key: 

 Header name: x-pan-token 

 Header value: your AIRS API key 

 Header naming rules.Anthropic reserves
 webhook-* , X-Anthropic-* , and
 Content-* prefixes, and requires hyphens
 (not underscores) in header names. `x-pan-token` complies with
 these rules. 

 Update the Prisma AIRS configured APP (step 6) in the Prisma AIRS console
 to enter the signing secret. After saving the Inference Hooks configuration,
 Anthropic displays a signing secret (prefixed). This secret is shown only
 once. 

 Consider the propagation
 window . For approximately one minute after a secret is
 first set, and just after a rotation, Anthropic may send requests that
 are unsigned or signed with the previous secret. The AIRS edge is
 configured to tolerate this window to avoid blocking all prompts across
 the organization during activation. 

 Test and activate: 

 In the Anthropic console, click Test
 connection . Anthropic sends a synthetic
 config-test frame. AIRS returns allow for these
 frames without logging. 

 Once the test succeeds, enable Enforce
 verdicts in the Anthropic console. Enforcement
 propagates within approximately one minute. 

 Runtime Flow 

 For each governed prompt, Anthropic: 

 Pauses inference. 

 POSTs a signed PromptFrame to the AIRS webhook
 endpoint. 

 Waits for a Verdict response within the configured
 verdict timeout (1–10,000 ms). 

 Enforces the verdict: allow continues inference;
 deny blocks it and shows deny_reason to the user. 

 Known Limitations 

 Text content only . Images, files, and binary
 attachments are not scanned. `tool_use` and `tool_result` blocks are
 carried but not inspected. 

 Prompt event only . Response-side enforcement is not
 yet supported. 

 US region only . 

 surface.application is advisory . This field is
 client-asserted and cannot be used as a security control.
