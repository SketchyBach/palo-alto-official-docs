 Migrate from VM-Series on NSX-T Operation to Security Centric
Deployment 

 Learn to migrate from VM-Series on NSX-T Operation to security centric
 deployment 

 Use the following procedure to migrate your
operations-centric NSX-T deployment to a security-centric NSX-T
deployment. 

 Log in to Panorama. 

 Modify the match criteria of your Dynamic Address Groups to follow the format
 required for a security-centric deployment. 

 Select Objects Address Groups . 

 Verify that you are configuring the Dynamic Address Groups in a device
 group associated with an NSX-T service definition. 

 Click on the name of a previously created NSX-T Dynamic Address Group.

 Edit the match criteria. 

 For the Dynamic Address Group to become a security group in NSX-T
 Manager, the match criteria string must be enclosed in single quotes
 with the prefix _nsxt_ followed by the exact name of the address
 group. For example,
 ‘_nsxt_PAN_APP_NSX’ . 

 Repeat this process for each security group you require. 

 Set the security rules to be as NSX-T steering rules
to intrazone. 

 In Panorama, select Policies Security Pre Rules . 

 Verify that you are configuring the security rules
in a device group associated with an NSX-T service definition. 

 Click Add and enter a Name and Description for
your security policy rule. 

 Set the Rule Type to intrazone (Devices
with PAN-OS 6.1 or later) . 

 In the Source tab, set the source zone to the zone from the template
 stack associated with the service definition. Then select a Dynamic
 Address Group you created previously as the Source Address. Do not add
 any static address groups, IP ranges, or netmasks as a Source
 Address. 

 In the Destination tab, Panorama does not allow you to set a
 destination zone because you set the rule type to intrazone. Then select
 a Dynamic Address Group you created previously as the Destination
 Address. Do not add any static address groups, IP ranges, or netmasks as
 a Destination Address. 

 Click OK . 

 Repeat steps 1 through 7 for each steering rule you
require. 

 Commit your changes. 

 Auto generate a new steering policy. 

 The following steps are for specifying service managers instead of selecting
 All . 

 Select Panorama VMware NSX-T Network Introspection Policy . 

 Click Auto Generate . 

 For Service Managers , choose
 Select . 

 If you select All instead of selecting
 specific service managers, the plugin will generate a steering
 policy for each service definition associated with each service
 manager in your configuration. 

 Click Add to select the service manager. 

 Select a Service Manager from the
 drop-down. 

 Click Add to select the service
 definitions. 

 Select the service definition from the drop-down. 

 Click OK and click OK 
 again. 

 Commit your changes. 

 Auto generate new steering rules. 

 If you autogenerate the steering policy, you must also autogenerate the steering rules. And if
 you manually create a steering policy, you must also manually create
 steering rules. 

 The following
steps are for specifying service managers instead of selecting All . 

 Select Panorama VMware NSX-T Network
Introspection Rule . 

 Click Auto Generate . 

 Select the type of Security rules from the
 drop-down— All , Pre
 Rulebase only, or Post Rulebase 
 only. The security rules are pulled from the service definitions
 specified in the following steps. 

 For Type , choose Select . 

 Click Add to specify the Service Manager (s)
and Service Definition (s). 

 Select a Service Manager from
the drop-down. 

 Click Add to select the service
 definitions. 

 Click OK . 

 Click OK to finish or Add to
specify additional service managers and service definitions. 

 ( Optional ) Click on an autogenerated rule to modify the
 default options. 

 Create Dynamic Address Group Membership Criteria . 

 Commit your changes to Panorama. 

 Delete the operations-centric steering rules from NSX-T
Manager. 

 Log in to NSX-T Manager. 

 Select Security Network Introspection (E-W) Rules . 

 Select each operations-centric steering rules. 

 Click Delete . 

 Delete the operations-centric service chain from NSX-T
Manager. 

 Log in to NSX-T Manager. 

 Select Security Network Introspection Settings Service
Chains . 

 Click the vertical ellipses. 

 Click Delete .
