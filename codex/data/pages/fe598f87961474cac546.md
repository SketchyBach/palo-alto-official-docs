# Deploy Koi to your endpoints

Deploy Koi to your endpoints

Go to Settings → Deployment and start a new deployment.

Step 1 - Set your deployment details

1. Deployment method - Choose the MDM or EDR your organization uses to deploy software to devices: Jamf, Intune, Kandji, CrowdStrike, SentinelOne and more.
Don't use any of these? Choose Manual. 

2. OS - Choose the operating system of the devices you want to protect, for example macOS.

3. Installation Method - Choose how Koi runs on the device:

Persistent Koi script package (recommended) - a persistent binary that handles the script execution by itself. Only initial deployment is needed, then it manages the execution cadence automatically. Available for macOS and Windows. The script is schedule to run each 1 hour. It can be customizable via the support exceptions.

Koi script package - the lightweight KOI script package, scheduled and run by your existing MDM or EDR. Koi uses the deployment infrastructure you already have, with no extra agent to install. Learn more on KOI script package here.

Note: Minimal performance impact expected for the persistent package integration
The persistent package runs Koi and nothing else: it executes the Koi script package on its schedule. No additional capabilities or kernel drivers are activated on the endpoint, so the impact on device performance is minimal.

Step 3 - Validate Integration

Confirm your devices are connected

Once the script or binary runs on your devices, it start reporting to Koi. Go back to Settings → Deployment to confirm everything is working.

Check the overall status

The deployment shows a Deployed badge when it's live.

Covered endpoints shows how many devices are connected, with a coverage bar so you can see your progress at a glance.

Check each script

Under Scripts, every script you deployed appears in its own row, showing the operating system, the number of endpoints reporting to it. 

See which devices are connected

Select the arrow on any script (or See endpoints) to open Covered endpoints, where you can see every device that script reached:

Hostname - the device name.

Last seen - when the device last reported to Koi.

Registered at - when the device first connected.

Script version - the version of the Koi script running on it.

Serial - the device serial number.

Step 4 - Roll out to the rest of your devices

When your test group looks healthy, widen the policy Scope in your MDM or EDR to the rest of your devices.
