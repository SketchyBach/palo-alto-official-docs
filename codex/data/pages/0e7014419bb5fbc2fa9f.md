Sensitive Data Exfiltration

Severity

🟠 High (7)

Short Description

Flags plugin or hooks that collect, transmit, or leak sensitive information — credentials, API keys, tokens, PII, or internal documents — to an external destination without a clear legitimate need or user consent.

Suggestion

Treat this as an active data-loss incident until proven otherwise. Determine what was sent and where, rotate any credentials that may have been exposed, and remove the component.

Information

This finding identifies code — a hook or plugin-level asset — that moves high-sensitivity material out of the environment. Credentials, API keys and tokens, personal data, and internal documents are the categories in scope; unlike the lower-severity data exfiltration finding, this is not telemetry or metadata.

Two properties drive the severity. The data is directly usable: a leaked API key grants whatever access it was issued for, immediately and without further exploitation. And the transmission is executable code rather than an instruction, so it runs automatically on agent events with no confirmation prompt in the path — a hook that reads environment files on file-write events sends data every time the event fires, across every project the developer touches on that machine.

Risks

Immediate credential compromise: Exfiltrated keys and tokens are usable by whoever receives them, without further exploitation.

Continuous exposure: Event-triggered hooks re-send data on every trigger for as long as they remain installed.

Regulatory and contractual breach: PII and internal documents leaving the environment can trigger notification obligations.

Lateral movement: Stolen credentials give access to systems well beyond the developer's machine.

Recommended Actions

Immediate action

Disable the component and isolate affected devices from the destination endpoint.

Rotate every credential the component could have accessed — environment files, token stores, SSH keys, and cloud credentials.

Block the destination at the network or proxy layer.

Investigate and remediate

Read the evidence to identify the exact data sources and destination endpoints.

Review network and agent activity logs to scope what was actually transmitted and when.

Determine which devices and users were affected and for how long.

Remove the plugin, review other components from the same publisher, and report it to the marketplace.

Engage your incident response process if regulated data was involved.
