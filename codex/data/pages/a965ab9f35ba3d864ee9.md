 Migrate from Cortex XSOAR 6 Multi-Tenant to Cortex XSOAR 8 Multi-Tenant using the migration wizard 

 Use the wizards to migrate your data from Cortex XSOAR 6 to 8. 

 Cortex XSOAR 6 Multi-tenant 

 This process uses the following wizards to help you migrate your data to each tenant in your multi-tenant deployment. 

 Pre-migration wizard 

 Sets up the Cortex XSOAR 8 migration tenant, such as sizing, retention, and dev/prod environments. 

 During the pre-migration wizard process, for development and child tenants, you can decide whether to migrate incident and indicator data. We recommend not migrating incident and indicator data for a quicker and more efficient migration process. 

 No data will be deleted from Cortex XSOAR 6 when you migrate your data. 

 Note 

 By default, each tenant (development and child tenant) has 6 months of incident retention. The retention period is calculated from the date the incident was created in Cortex XSOAR. All migrating customers receive an additional six months of retention until the end of the license term, regardless of whether they migrate incident and indicator data. For more information about retention, see Retention Policy . 

 If migrating incident and indicator data, you can select a retention period in the development and child tenant pre-migration wizard. 

 After completion of the pre-migration wizard, data is synced from Cortex XSOAR 6 to 8. 

 Migration wizard 

 Verifies that your data and content are synced in each activated tenant and that your integrations work correctly. 

 During this UAT phase, you are responsible for content propagation during the migration process. When you push content from the Cortex XSOAR 6 main tenant, only Cortex XSOAR 6 child tenants are updated. Cortex XSOAR 8 tenants must be updated from the Cortex XSOAR 8 development (if activated) or main tenant. When logging into the Cortex XSOAR 8 development or main tenant, you will see a notification to install content. 

 Important 

 For child tenants, you have up to 60 days from the date of the initial data sync to complete the switchover. For development and main tenants, you have up to 90 days. 

 Before you begin 

 Review the Migration Prerequisites for Cortex XSOAR 8 SaaS Multi-Tenant . 

 After receiving notification by email that your Cortex XSOAR 6 instance will be migrated, you need to provide details of administrators who will manage the migration. After the migration process starts, you can add or delete these administrators in the Cortex Gateway. 

 In each Cortex XSOAR 6 server, review the recommendations by going to Settings → About → Migration . 

 How to migrate to Cortex XSOAR 8 using the wizards 

 mt-wizard-migration-flow.png 

 Step 

 Description 

 Step 1. Activate Cortex XSOAR 8 SaaS Multi-Tenant 

 In Cortex Gateway, activate in the following order: 

 1. Main tenant 

 2. Development tenant and child tenant 

 It doesn't matter if you activate a child tenant before a development tenant. 

 Note 

 If you have a Cortex XSOAR 6 multi-tenant/MSSP license (for example, PAN-DEMISTO-MSSP), in Cortex XSOAR 8, you can activate a main tenant and one child tenant. 

 If you need to activate more child tenants or a development tenant, contact Customer Support to see how to obtain additional licenses. 

 Step 2. Set up Cortex XSOAR 8 Multi-Tenant using the Pre-migration Wizard 

 Sets up your Cortex XSOAR 8 tenants, ensures connectivity, and starts an initial data sync. 

 We recommend completing the pre-migration wizard steps in the following order: 

 1. Development Tenant (if activated) 

 If using a development tenant, we recommend configuring this tenant first, as you install and configure content on the development tenant. 

 2. Main Tenant 

 As configuration and content propagate from the main tenant to the child tenant, you should configure the main tenant before the child tenant. If you initially sync a child tenant, it will not contain any data, as you have not yet synced the main tenant. 

 3. Child Tenant 

 During the pre-migration wizard stage, for development and child tenants, you can decide whether to migrate incident and indicator data. 

 Step 3. Run user acceptance tests (UAT) in a Multi-Tenant Deployment using the Migration Wizard 

 The wizard guides you through the User Acceptance Test (UAT) process, enabling you to test, review, and approve the changes, such as incidents and indicator data, integrations, jobs, and users and roles. 

 Note 

 Incidents, indicator data, and jobs are not relevant to the main tenant. 

 Although you can run tests using the migration wizard in any tenant order, you must complete the switchover on each child tenant before switching over the main and development tenants. 

 Step 4. Select whether to resync data and set the switchover on Cortex XSOAR 8 SaaS multi-tenant 

 After completing the UAT stage, decide whether you want to resync data and set the switchover date, if relevant. The switchover must take place in the following order: 

 1. Child tenant 

 On the child tenant, you must switch over before the main tenant. When you switch over, the main tenant syncs content from the child tenant. You also want the development tenant to switch over before the main tenant (production tenant). There is no data resync on the main tenant, as the main tenant doesn't hold incident data. 

 2. Development tenant (if activated) and main tenant 

 It does not matter if the development switchover is before or after the main tenant. We recommend the development tenant first, as it minimizes downtime for content and configuration resync. 

 At switchover, if data is resynced (not on the main tenant), it is migrated. 

 Note 

 If you want to roll back the migration, contact Customer Support within 30 days of each tenant switching over to Cortex XSOAR 8. 

 Post Migration Steps for Cortex XSOAR 6 Multi-Tenant to 8 SaaS Multi-Tenant 

 Validate settings and data. If you have decided not to migrate incident and indicator data, consider moving your incidents and indicators.
