 Step 2. Set up Cortex XSOAR 8 Multi-Tenant using the Pre-migration Wizard 

 Configure a remote repository for multi-tenant using the pre-migration wizard 

 In Cortex Gateway, when hovering over the main tenant, you can activate a child and development tenant (subject to your license). Child tenants cannot use a development tenant. After activation, you can set up the remote repository in the pre-migration wizard. 

 However, before you select the remote repository in the pre-migration wizard, in Cortex XSOAR 6, ensure that the Content Repository type and server type (Production/Development) on the license page are aligned with the correct environment. 

 Align the content repository types in Cortex XSOAR 6 

 Check the Content Repository type. 

 Go to Settings → ADVANCED → Content Repository . 

 You can see whether the server is either Production or Development. 

 remote-repo-6.png 

 Check the server type. 

 Go to Settings → ABOUT → License . 

 You can see whether the Server Type is either Production or Development. 

 server-type.png 

 Content repository types in Cortex XSOAR 8 

 The pre-migration wizard detects whether you use a remote repository in Cortex XSOAR 6. In Cortex XSOAR 8, you have the following options: 

 Repository type 

 Git Branch 

 Description 

 Built-in content repository 

 Single branch 

 This is the default migration process. 

 Private repositories with a single Git branch can migrate to the built-in content repository. Those with multiple branches either need to switch to a single branch or provide new branch details and switch to migrate to a private remote content repository. 

 Tip 

 For a single Git branch deployment, we recommend using the built-in repository. 

 After the pre-migration wizard steps are completed, the initial data sync starts and a Git branch is created in the built-in content repository. The Cortex XSOAR 8 tenant replicates the content from the Cortex XSOAR 6 environment (development 6 to development 8, production 6 to production 8). 

 Private content repository 

 Single/multiple branches 

 If using a single or multiple Git private repositories, add the new branch names in the pre-migration wizard. The pre-migration wizard automatically creates the branch on your remote repository. 

 Make sure that you use the same name in dev/prod tenants. 

 Important 

 To avoid losing changes from the Cortex XSOAR 6 production machine private content repository, pull all changes from the production machine repository before the initial sync. 

 If you select a single branch, after the initial data sync, a single branch is created in the UAT. You can only change the selection after migration. 

 After the pre-migration wizard steps have been completed, the initial data sync starts, and a Git branch/branches are created in the private content repository. The Cortex XSOAR 8 environment replicates the content from the Cortex XSOAR 6 environment (development 6 to development 8, production 6 to production 8). 

 Note 

 The development and production environments must use the same remote repository type. 

 If you want to switch remote content repository types, we recommend switching after migration.
