# Access Agent Configuration

For the complete documentation index, see llms.txt. This page is also available as Markdown.

Access Agent Configuration

Severity

🟡 Medium (4)

Short Description

Flags MCP servers, plugin hooks, and plugin-level assets that read or modify the agent's own configuration files. Unauthorized configuration access can silently change tool permissions, model selection, or safety settings for every later session.

Suggestion

Determine whether configuration access is required for the server or hook to function. Where it is, scope it to the specific files needed. Remove or replace the component if the access is broader than its purpose requires.

Information

This is the executable counterpart to Access Agent Configuration Instruction. Rather than asking the agent to touch its configuration, the MCP server, hook, or plugin asset reads or writes those files directly with its own process privileges.

That difference matters. There is no agent judgment and no user confirmation in the path — when the hook fires or the MCP tool runs, the file operation happens. Hooks in particular are triggered by agent events rather than by an explicit user action, so configuration can change during ordinary work without anyone initiating it.

Because agent configuration governs tool permissions, model selection, MCP server definitions, and safety settings, a component that can rewrite it can effectively re-scope the agent for every session that follows.

Risks

Unattended modification: Hooks run on agent events, so configuration can be rewritten with no user action and no visible prompt.

Full-privilege file access: The component operates with its own process privileges rather than through the agent's mediated tool layer.

Fleet-wide persistence: Once written, the configuration applies to all subsequent sessions on that machine.

Self-reinforcing changes: A component that can edit configuration can grant itself or another component broader permissions, or disable the controls that would flag it.

Recommended Actions

Investigate the component

Use the evidence to identify the exact configuration paths accessed and whether writes are involved.

For hooks, check which events trigger the access and how often they fire.

Confirm the behavior is documented by the publisher.

Contain and remediate

Audit the current agent configuration on affected devices for unexpected entries, especially added MCP servers and widened permissions.

Run the MCP server with least-privilege filesystem access.

Remove the component and restore a known-good configuration if the access is unjustified.
