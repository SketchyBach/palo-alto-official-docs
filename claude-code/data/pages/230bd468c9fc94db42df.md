# Access Agent Configuration Instruction

Access Agent Configuration Instruction

Severity

🟡 Medium (4)

Short Description

Flags AI extensions that instruct the agent to read or modify its own configuration files. Unauthorized changes can silently alter tool permissions, model selection, or safety settings for every later session.

Suggestion

Confirm that configuration access is part of the component's stated job. Setup and onboarding helpers legitimately edit configuration; a component with an unrelated purpose should not. Remove or replace the component if the access is unexplained.

Information

The agent's configuration files — settings, permission allowlists, MCP server definitions, model selection, and enabled extensions — determine what the agent is allowed to do. A skill, command, subagent, or rule that tells the agent to read or edit those files is asking to change the boundaries the agent operates within.

The change is durable. Unlike a one-off action, a configuration edit persists across sessions and applies to every later conversation, including ones that have nothing to do with the component that made the change. Because the edit happens through the agent rather than through a settings UI, the user may never see that the agent's permissions have shifted.

Configuration access is not inherently malicious. Setup helpers, workspace bootstrap commands, and "configure my environment" skills read and write configuration by design. The evidence tells you which files are involved and what the component asks the agent to do with them.

Risks

Silent permission expansion: A tool-permission allowlist can be widened so later actions no longer prompt for approval.

Weakened safety posture: Confirmation prompts, restricted-path settings, or guardrail configuration can be relaxed or removed.

Persistent effect: The change outlives the session that made it and affects unrelated future work.

Injected capability: New MCP servers or extensions can be added to the configuration, giving the agent capabilities the user never chose.

Recommended Actions

Investigate the component

Read the evidence to identify which configuration files it targets and whether it reads, writes, or both.

Check whether configuration access matches the component's stated purpose.

Verify the publisher and review what changed if this appeared in a recent version.

Contain and remediate

Compare the agent's current configuration against your expected baseline and revert unexpected changes.

Restrict the component's file access to sensitive paths while under review.

Remove the component if configuration access cannot be justified.
