 Panorama Support for Prisma Access 6.1 

 Prisma Access Addressed Issues 

 Lists the known issues in Prisma Access 6.1.0. 

 The following table lists the issues addressed in Prisma Access 6.1.0. 

 Prisma Access 6.1.1 Addressed Issues 

 Issue ID 

 Description 

 CYR-62527 Fixed an issue where syslog config filters out NAT
 tunnel alerts to be sent out to Strata Logging Service. 

 CYR-62135 Fixed an issue where, in a multitenant Panorama
 managed Prisma Access deployment, internal host detection could not
 be configured by device group and template admin users. 

 CYR-60959 Fixed an issue where, when enabling Private
 Application Access in Explicit Proxy and ZTNA Connector is also
 configured, an error message displayed that there was not a service
 connection deployed. 

 CYR-59967 Fixed an issue where, for RN-HP sites in OCI
 regions, maximum bandwidth per tunnel supported is 2Gbps because of
 OCI limiting per-flow traffic from their side. 

 CYR-58965 Fixed an issue where Panorama did not send the
 onboarding commit job to the back end when onboarding Service
 Connections, requiring a secondary push to properly trigger the
 commit job for Service Connections. 

 CYR-54776 Fixed an issue where BGP filtering was enabled on a
 Panorama in a multi-tenant deployment that had no supertenant. BGP
 filtering is not supported on a Panorama in a multi-tenant
 deployment that has no supertenant. 

 CYR-55477 Fixed an issue where, when using a site-based
 license, the allocated and available bandwidth for remote networks
 was incorrectly shown as 0 in the Panorama status page. 

 Prisma Access 6.1.0-h9 Addressed Issues 

 Issue ID 

 Description 

 CYR-70786 Fixed an issue where, in multi-tenant Panorama,
 plugin validation fails upon bulk import operation of the remote
 network configuration. The issue occurred only when the remote
 network had secondary WAN configuration enabled. 

 CYR-67720 Fixed an issue where you could not enforce Transport
 Layer Security (TLS) version 1.3 as the minimum TLS version for the
 default domain, which prevented you from utilizing the latest
 security protocols. With this fix, you can now configure TLSv1.3 as
 the minimum TLS version for the default domain. 

 CYR-69289 Fixed an issue where Prisma Access Multi-tenant
 customer Fast Session Delete feature enablement was not taking
 effect upon commit push. 

 Prisma Access 6.1.0-h8 Addressed Issues 

 Issue ID 

 Description 

 CYR-63001 

 Effective May 29, 2026, PRA has been officially rebranded as
 Secure Agentless Access (SAA). This update introduces an
 expanded range of supported applications and a modernized user
 experience for both administrators and end users. 

 Key Changes and Enhancements 

 Modernized UI: The new user interface and updated navigation
 are now live directly in the Strata Cloud Manager (SCM)
 front end. 

 Panorama Integration: Panorama now features a cross-platform
 launch panel reflecting the new SAA identity. 

 Private Web Apps Support: You can now configure private web
 applications (HTTP/HTTPS) as a new application type. 

 Licensing Updates: Private Web Apps support is included with
 Prisma Access base licensing (ZTNA and Enterprise editions).
 Supporting RDP, SSH, and VNC application types still require
 the existing add-on license. 

 Prisma Access 6.1.0-h7 Addressed Issues 

 Issue ID 

 Description 

 CYR-67282 Fixed an issue where the NGFW Connector was failing
 in staging and production environments. 

 CYR-66709 Fixed an issue where the Export Remote Networks
 configuration did not work when the Remote Networks Template IKE
 Gateway was configured with a Peer IP Address
 Type as IP instead of Dynamic. 

 CYR-66504 Fixed an issue where failures were encountered (for
 example, the response was empty) when the CA certificate was being
 requested by Strata Logging Service. 

 CYR-66409 Fixed an issue where service connection onboarding
 might not display properly when the administrator creates a
 sub-tenant's name with the "remote-networks" keyword. 

 CYR-66277 

 Fixed an issue where, for Prisma Access Cloud Service plugin when
 IP optimization was enabled and IP Allowlist was enabled, there
 was a change and difference detected in the configuration
 between the cloud and the configuration, which pushed an empty
 change. Because of this action, any changes made by the
 administrator would be attributed to the __cloud_services user
 instead of the admin user that made the change. 

 CYR-65555 Fixed an issue where, in a Multitenant Panorama, the
 IPv6 option could be enabled in IKE Gateway and IPsec Tunnel
 templates even if IPv6 WAN was disabled in the Cloud Services
 Plugin. 

 CYR-63794 Fixed an issue where, if the Panorama license was
 renewed after its expiration, the cloud services OTP workflow and
 license capability fetch workflow did not complete without manually
 deleting the stale/expired license key files.

 Issue ID 

 Description 

 CYR-58852 

 Fixed an issue where Panorama commit validation workflows would
 fail if a tenant's licenses had the "no_limit" string under the
 service_connection local service chain information in the
 license_capabilities. This occurred because the system was
 attempting to convert the string to an integer.

 Fixed an issue where commits to GlobalProtect gateways failed
 with a validation error related to the `max-version` setting in

 the "Enable Private App Access" option. When this configuration
 was pushed to Prisma Access, it caused an outage to critical
 internal applications.

 Fixed an issue where any changes to the Cloud Services Plugin
 onboarding configuration on Panorama resulted in an error when
 the 'DEFAULT' config was missing in the GlobalProtect

 CYR-57636 

 Fixed an issue where Panorama could not display bandwidth usage
 statistics for remote networks in the tenant status view when
 managing Prisma Access with multitenancy enabled. 

 CYR-55432 

 Fixed an issue where Internal Host Detection (IHD) details were
 grayed out during Mobile User onboarding. 

 CYR-54503 

 Fixed an issue where domain configurations were not applied to

 configurations were successfully applied to remote networks.

 Fixed an issue where, when onboarding remote networks using
 configuration import in a multitenant deployment, an import
 error was seen. 

 CYR-51619 

 Fixed an issue where, after creating a new regional IP pool for

 received in the Cloud services plugin UI.
