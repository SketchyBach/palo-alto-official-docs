 About CA Accounts 

 To issue trusted certificates to workloads, Distributed Issuer needs its own certificate authority (CA) certificate to be signed by a trusted parent authority. 

 A CA account connects Distributed Issuer to that parent authority. When Distributed Issuer starts, it uses the CA account to obtain a signed CA certificate, which places Distributed Issuer in your organization's trust chain. 

 Connecting a CA Account 

 To connect a CA account, follow the instructions for your CA type. Distributed Issuer supports any CA that supports subordinate CA certificates, including: 

 Zero Touch PKI : Connect to a Zero Touch PKI instance using an API key . 

 Microsoft Active Directory Certificate Services : Connect to Microsoft AD CS through a VSatellite . 

 Note : Skip adding a CA if using the built-in CA, which already exists in your account. The built-in CA is designed for non-production environments only. 

 What's Next? 

 Once you have connected a CA account, create a Subordinate CA provider that defines the properties of Distributed Issuer's CA certificate and links it to the CA account that will sign it.
