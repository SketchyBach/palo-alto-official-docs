# Suspicious password change alerts

Skip To Main Content
Our Products
Suspicious password change alerts

This topic describes suspicious password change alerts, which trigger when the password of a fully managed privileged account is changed or reset directly on the endpoint, without going through the Secret Rotation Service. This alert might indicate an unauthorized user or attacker attempting to bypass automated credential management.

Suspicious password change alerts trigger when a password is manually changed or reset on the following machines:

Windows on-premises and cloud-hosted machine/VM

*nix on-premises and cloud-hosted machine/VM

Threat Detection and Response integrates with your SIEM system to forward password change events, which it analyzes against the accounts managed in the Idira PAM Vault.

If a suspicious password change is detected, you receive an alert and can review and investigate it in the Security alerts feed.

Alert details

A suspicious password change alert includes the following details:

Suspicious password change alert details

Field

	

Description




Account name

	

The privileged account whose password was changed.




Account domain

	

The domain of the affected account.




Change action

	

Change password for a self-change, or Reset password for an admin-initiated reset.




Subject account

	

The user who performed the reset. Applies only when the change action is Reset password.




Subject account domain

	

The domain of the subject account.




Target address

	

The address of the machine on which the password was changed or reset.




Link to specific account

	

A direct link to the account in Privilege Cloud.

Considerations and expected behavior

It can take approximately 24 hours for newly onboarded accounts to be assessed by suspicious password change detection. During this period, you do not receive suspicious password change alerts on accounts that are already being managed in the PAMVault.

Suspicious password change only supports accounts that are stored in the PAMVault with an address of FQDN or hostname. Accounts stored by IP address are not currently supported.

For a self-change, suspicious password change events do not contain information about the user who changed the password.
