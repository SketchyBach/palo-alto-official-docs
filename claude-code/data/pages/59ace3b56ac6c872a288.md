 Troubleshoot Incidents 

 Follow the troubleshooting steps for resolving incidents generated in Prisma SD-WAN . Follow the troubleshooting steps for each incident in the
 order listed. Each step is intended to resolve the issue. 

 Where Can I Use This? What Do I Need? 

 Prisma SD-WAN (Managed by Strata Cloud Manager ) 

 Prisma SD-WAN 

 Prisma SD-WAN generates incidents and alerts when the system reaches
 system-defined or customer-defined thresholds or there is a fault in the system. Use the
 incident and alert event codes to view the
 details of the incidents and alerts generated in the system. 

 Follow the troubleshooting steps for each incident in the order listed
 below. Each step is intended to resolve the issue. Proceed to the next step only if the
 previous step did not resolve the problem. 

 For each incident raised, you can select Troubleshoot 
 to follow a step-by-step troubleshooting procedure. If the issue persists, select
 Go to Support to create a support ticket. A Palo Alto
 Networks Support executive will contact you. You can also return the device to Palo Alto Networks. 

 Incident Code Troubleshooting Steps CATEGORY SUB-CATEGORY 

 INC_SDWAN_APPLICATION_CUSTOM_RULE_CONFLICT 

 Select Incidents Prisma SD-WAN Incidents . 

 Locate the required application for troubleshooting. 

 Click the ellipsis under Action and
 select Troubleshoot . 

 If the Application has an override, you may need to access
 the override rules to make the shift, possibly before
 clicking the ellipsis. 

 You can make changes on the App configuration screen. 

 Configuration Network Best Practice & Compliance 

 INC_SDWAN_DEVICEHW_DISKENC_SYSTEM 

 This event code was raised when one disk partition failed to convert
 into an encrypted partition during the last device upgrade. 

 Go to Configuration Prisma SD-WAN ION Devices Claimed Devices . 

 Locate your device and click Upgrade 
 in the Software column. 

 Select the required software version to upgrade. 

 After the upgrade is complete, repeat the same steps and
 downgrade to the target version. If the target version is
 the latest and you still see the error, upgrade to the
 version before the latest and then upgrade to the latest
 again. 

 Device System Resources 

 INC_SDWAN_DEVICEHW_DISKUTIL_PARTITIONSPACE 

 This event code is raised due to high disk capacity utilization. To
 verify, follow the steps: 

 SSH to the device and run the command:

 dump disk info 

 Check the available space for the attached volumes and
 contact the Palo Alto Networks Support team to clear the
 utilized volume. 

 Device System Resources 

 INC_SDWAN_DEVICEHW_INTERFACE_ ERRORS 

 This event code is raised due to a faulty cable, SFP, port, or patch
 panel connection. 

 Inspect and replace the cable. Ensure that the correct cable is
 used. 

 If the port requires a transceiver, replace the SFP. Ensure
 that the SFP is correct. 

 Try a different patch panel port if you are using a patch
 panel. 

 Attempt using a different port on the ION device. 

 Inspect the device and port that the ION device connects to.
 Sometimes the issue could be due to the other hardware
 device. 

 INC_SDWAN_DEVICEHW_INTERFACE_HALFDUPLEX 

 This event code is raised due to issues with port configuration and
 cable. First, verify the cable connection and swap the cable.
 Second, check the port and the remote end (auto or hard-coded). To
 change the port configuration: 

 Locate your device and click it. 

 Go to Interfaces and select the
 interface with half/duplex. 

 Select Advanced Options - PHYSICAL and
 change it. 

 Verify if the connection is UP and has a correct
 configuration with full-duplex 

 Configuration Device Best Practice & Compliance 

 INC_SDWAN_DEVICEHW_INTERFACE_DOWN Interface down requires an assessment to see if the
 incident is intentional or real. 

 SSH to the device and run the commands: 

 dump interface status <port number> 

 dump interface config <port number> 

 Check if the port is admin up and connected/not
 connected.

 To verify if High Memory Utilization is happening in real-time: 

 Select Configuration Prisma SD-WAN ION Devices Device List Device Activity . 

 Select the ION device and confirm the free memory. 

 SSH to the device and run the

 Device System Resources 

 INC_SDWAN_DEVICEHW_POWER_LOST This event code is raised by an unplugged or a loose
 power cable. 
 Try using a new cable or re-seating the existing cable. If this
 does not help, replace the power supply unit (PSU). Note down
 which PSU failed for devices that have dual PSUs. Order a
 replacement PSU from Palo Alto Networks for the particular ION
 device. 

 When the new PSU is available on hand at the device's site,
 pull out and replace the affected PSU. 

 Device System Resources 

 INC_SDWAN_DEVICEIF_ADDRESS_DUPLICATE If static IP address configuration is used, confirm that
 the IP address used is not explicitly assigned to another device or
 within a range already allocated by a DHCP server. Device System Resources 

 INC_SDWAN_DEVICESW_CONCURRENT_FLOWLIMIT_EXCEEDED 

 To verify the concurrent flows: 

 Select Configuration Prisma SD-WAN Branch Sites . 

 Select the ION device and verify the concurrent flows
 generated by UDP/TCP packets and time. 

 Verify in Flow Browser for the same
 flow, the source/destination IP address initiating multiple
 sessions. Then, based on the source/destination IP address,
 confirm a network scanning in the environment. 

 Device System Resources 

 INC_SDWAN_DEVICESW_DHCPRELAY_ RESTART Process stopped requires further investigation. Contact
 Palo Alto Networks Support. Device System Resources 

 INC_SDWAN_DEVICESW_DHCPSERVER_ERRORS 

 Check interfaces configuration and state. 

 Verify that at least one device interface is active and
 configured with static IP configuration. 

 Check DHCP server configuration. 

 Verify that the subnet address does not overlap across the
 site. 

 If custom options are configured, verify that the custom
 option definition and option value are compatible with each
 other. 

 If the problem still persists, contact Palo Alto Networks
 Support. 

 INC_SDWAN_DEVICESW_DHCPSERVER_RESTART Process stopped requires further investigation. Contact
 Palo Alto Networks Support. Services DHCP 

 INC_SDWAN_DEVICESW_DISCONNECTED_FROM_CONTROLLER 

 Check if there is any network connectivity problem at the
 site. Look for invalid interface configurations, interface
 incidents or network incidents. If present, clear those
 faults. 

 Check if there are any process incidents which indicate that
 processes are stopped. If present, take action on those
 faults. 

 Check if any firewall rules both on the ION device (if used)
 and external to the ION device prevent communication between
 the ION device and controller. If present, fix those
 rules. 

 Ensure that the controller is not undergoing maintenance. If
 notification indicates maintenance activity, wait until the
 activity is completed. 

 If none of the choices apply, please open a case with Palo
 Alto Networks Support.

 INC_SDWAN_DEVICESW_IMAGE_INCOMPATIBLE 

 Check the software version of the device on the
 Device List screen. 

 Click Upgrade and check if the
 device's software version is present in the available
 software list. 

 If the software version on the device is not on the available
 software list, upgrade or downgrade the device to an
 available software version. After successful software
 change, issue Recheck SW Version command
 from the device list for that device. 

 If the software version is not on the available software list
 but the software version on the device is the desired
 software version for your network, contact Palo Alto
 Networks Support for further instructions.

 INC_SDWAN_NETWORK_DIRECTINTERNET_DOWN (Branch sites only) 

 Check if there are any interface down incidents on the
 interfaces connecting to the internet circuit. 

 Log in to the device via SSH/Remote
 access . 

 Verify internet interface status and reachability on the
 interface by pinging public IP addresses. 

 Check the ARP entry of the gateway IP address on the internet
 interface by running the inspect system arp command. 

 Capture packets on the internet interface and verify the
 packet flow. 

 Check the internet modem, if present, to ensure that it is
 powered up. Then, as a possible recovery step, power cycle
 the modem. 

 If the problem persists, contact Palo Alto Networks
 Support. 

 Device System Resources 

 INC_SDWAN_NETWORK_DIRECTPRIVATE_DOWN (Branch sites only) 

 Check if there are any interface down incidents on the
 interfaces connecting to private WAN routing devices. Then,
 follow interface troubleshooting and incident clearance
 procedures for that interface. 

 Log in to the device via SSH/Remote
 access . 

 Verify interface status and reachability by pinging the
 gateway IP address. 

 Check if connectivity between the remote office and the data
 center exists by pinging a data center’s private WAN
 interface(s) IP addresses from the affected site. 

 Verify BFD connectivity between the remote office and the
 data center private WAN interface(s) IP addresses. 

 Capture packets on the Private wan interface and verify the
 packet flow. If the problem still persists, contact Palo
 Alto Networks Support.

 remove one of the rules to ensure that there is no conflict. Network & Traffic Interface 

 INC_SDWAN_NETWORK_POLICY_RULE_DROPPED Update the identified policy rule to remove some

 INC_SDWAN_NETWORK_PRIVATEWAN_DEGRADED (DC Sites only) 

 Verify that the prefixes configured on the remote site are
 correct. 

 Verify that the BGP configuration on the WAN edge router is
 such that routes sent to the Palo Alto Networks data center
 device are received from the provider without any
 summarization. 

 Network & Traffic Interface 

 INC_SDWAN_NETWORK_PRIVATEWAN_UNREACHABLE (DC Sites only) 

 Check if there are any interface down incidents on the
 interfaces connecting to private WAN routing devices. Follow
 interface troubleshooting and incident clearance procedures
 for that interface. 

 Check if local network endpoints connected to the affected
 ION device are reachable by pinging the interface through
 which the private WAN traffic is supposed to traverse. 

 For a data center site, check for PEERING_EDGE_DOWN
 incidents. Follow PEERING_EDGE_DOWN troubleshooting and
 incident clearance steps. 

 Check if connectivity between the remote office and the data
 center exists by pinging the private WAN interface(s) from
 the affected site. From a data center site, choose one or
 more remote office sites to ping to. 

 If the problem still persists, contact Palo Alto Networks
 Support. 

 Network & Traffic Interface 

 INC_SDWAN_PEERING_BGP_DOWN 

 Check if there are any interface down faults on the
 interfaces connecting to peer routing devices. Follow
 interface troubleshooting and fault clearance procedures for
 that interface. 

 Check if local network endpoints connected to the affected
 ION device are reachable using a ping operation using the
 interface through which traffic to peer routing device is
 supposed to traverse. 

 Check and validate configuration on the peer routing device
 and check for interface and routing faults. 

 If none of the choices apply, please open a case with Palo
 Alto Networks support

 INC_SDWAN_SPOKEHA_MULTIPLE_ACTIVE_DEVICES 

 Check the operational state of the interfaces that are
 specified as the source interface for cluster operation to
 find out if they are up. 

 If the interfaces on both devices are up, check the switch
 configurations to confirm the interfaces are in the same
 VLAN. 

 Ping the IP address on the interface on one of the devices
 from the other device to confirm the connectivity between
 the devices.
