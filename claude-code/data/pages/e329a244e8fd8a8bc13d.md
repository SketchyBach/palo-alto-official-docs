# Authenticate Secure Workload Access workloads with Google Cloud

Authenticate Secure Workload Access workloads with Google Cloud

This topic describes how to integrate Secure Workload Access (SWA) with Google Cloud so that your workloads can exchange SWA-issued JWT identities for temporary Google Cloud credentials.

Use this integration when your workloads need access to Google Cloud resources without long-term Google Cloud credentials.

Before you begin

The following prerequisites apply to all Google Cloud integrations.

Complete a Secure Workload Access (SWA) setup workflow. For more information, see Secure Workload Access: Unified workload identity with SPIFFE.

Review the supported OIDC issuer values for SWA integrations. For more information, see Configure OIDC issuer values for Secure Workload Access integrations.

Review the supported JWT signing algorithms and audience values for Google Cloud. For more information, see Configure JWT requirements for Secure Workload Access integrations.

Use a Google Cloud account with the IAM roles required to create workload identity pools and providers. Assign roles/owner, or if roles/owner is too permissive, assign both of the following:

roles/iam.workloadIdentityPoolAdmin

roles/iam.serviceAccountAdmin

Identify the Google Cloud service account that your workload will impersonate. You select this service account in Step 3. If you do not have one, create it in the Google Cloud Console under IAM & Admin > Service Accounts.

Identify the Google Cloud resources that your workload needs to access.

Install and authenticate the Google Cloud CLI. Steps 4 and 5 of this procedure use gcloud commands.

Configure Google Workload Identity Federation

Use these procedures to configure Google Workload Identity Federation to trust SWA-issued JWT identities, exchange those identities for Google Cloud credentials, and verify the integration. For more information about Workload Identity Federation concepts, see Workload Identity Federation on the Google Cloud website.

Step 1: Create a Workload Identity Pool
To create the Workload Identity Pool:

Open the Google Cloud Console and go to IAM & Admin > Workload Identity Federation.

Click + Create Pool at the top of the page.

Enter a name for the pool, for example, swa-pool.

Click Create Pool.

Step 2: Add an OIDC provider
To add the OIDC provider:

In the pool, click Add a Provider and select OpenID Connect (OIDC).

Enter a provider name, for example, swa-provider.

Enter the SWA issuer URL as the provider URL. To retrieve the issuer URL, see Configure OIDC issuer values for Secure Workload Access integrations.

 	

The issuer URL must be a public, unauthenticated HTTPS URL.

Under Allowed Audiences, enter the full provider resource name as the audience value: https://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/swa-pool/providers/swa-provider

Replace ${PROJECT_NUMBER} with your numeric project number. This value must exactly match the --audience value you use in Steps 4 and 5.

 	

Use the Google Cloud project number, not the project ID. The project number is a numeric value. To find it, go to IAM & Admin > Settings in the Google Cloud Console.

Add the provider.

Under Configure Provider Attributes > Mappings, set google.subject to assertion.sub.

Step 3: Grant access to a Google Cloud service account and restrict the SPIFFE ID
To grant access:

Select the pool you created in Step 1, for example, swa-pool.

Click Grant Access at the top of the page.

In the slide-over panel, under Service Account, select the Google Cloud service account that your workload impersonates.

Under Select principals, configure the principal restriction:

Set Attribute name to subject.

Set Attribute value to the SPIFFE ID that your workload receives from SWA attestation, for example, spiffe://prod.example.com/k8s-nodegroup/ns/my-namespace/sa/my-service-account. For SPIFFE ID formats, see Understand SPIFFE workload identities.

Save the changes.

Step 4: Exchange the JWT for Google Cloud credentials

Create a credential configuration file so that Google Cloud client libraries handle the token exchange. In the commands in this procedure, replace ${PROJECT_NUMBER} with your numeric project number and ${PROJECT_ID} with your project ID string. Alternatively, export both variables before running the commands.

 	

The paths in this procedure, such as /run/swa-agent/, are examples. Adjust them to match your SWA agent installation.

 	

The commands in this procedure require a Linux shell environment (Bash).

To create the credential configuration:

Create the credential configuration file.

 	

Use the Google Cloud project number, not the project ID. The project number is a numeric value. To find it, go to IAM & Admin > Settings in the Google Cloud Console.

 	
gcloud iam workload-identity-pools create-cred-config \
  "projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/swa-pool/providers/swa-provider" \
  --output-file="/run/swa-agent/gcp-creds.json" \
  --credential-source-file="/run/swa-agent/gcp.jwt" \
  --subject-token-type="urn:ietf:params:oauth:token-type:jwt" \
  --service-account="SERVICE_ACCOUNT@${PROJECT_ID}.iam.gserviceaccount.com"

Replace SERVICE_ACCOUNT with the name of the service account you selected in Step 3.

Set the GOOGLE_APPLICATION_CREDENTIALS environment variable to the credential configuration file path.

 	
export GOOGLE_APPLICATION_CREDENTIALS="/run/swa-agent/gcp-creds.json"

Fetch the SWA JWT-SVID and extract the token. The swa-agent api fetch jwt command returns formatted output with metadata. Extract only the JWT token from the second line.

 	
/opt/swa/bin/swa-agent api fetch jwt \
  --audience https://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/swa-pool/providers/swa-provider \
  --socketPath /run/swa-agent/api.sock > /run/swa-agent/gcp-raw.txt

sed -n '2p' /run/swa-agent/gcp-raw.txt | tr -d '[:space:]' > /run/swa-agent/gcp.jwt

Use the credential configuration with the Google Cloud client library or tool that your workload needs.

Step 5: Verify the Google Cloud integration

Confirm that your workload can authenticate to Google Cloud and access the resource you configured. You can run these steps from any workload that has a SPIFFE identity from SWA.

To verify the integration:

Verify that the SWA agent is running on the workload host.

Request a JWT-SVID with the Google Cloud audience and confirm that the output shows a SPIFFE ID and JWT token.

 	
/opt/swa/bin/swa-agent api fetch jwt \
  --audience https://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/swa-pool/providers/swa-provider \
  --socketPath /run/swa-agent/api.sock

The output shows the SPIFFE ID and JWT token:

 	
token(spiffe://prod.example.com/k8s-nodegroup/ns/my-namespace/sa/my-service-account):
        eyJhbGci...
bundle(...):
        {"keys":[...]}

Set GOOGLE_APPLICATION_CREDENTIALS and verify access to the Google Cloud resource using gsutil.

 	

The gcloud auth print-access-token command does not work with Application Default Credentials. Use gsutil or a Google Cloud client library instead.

 	
export GOOGLE_APPLICATION_CREDENTIALS="/run/swa-agent/gcp-creds.json"
gsutil cat gs://${BUCKET_NAME}/<object-name>
Troubleshoot the Google Cloud integration

Use this section to address common errors that occur when workloads exchange SWA-issued JWTs for Google Cloud credentials.

Attribute mapping error

The google.subject attribute mapping must be set correctly in the Workload Identity Federation OIDC provider. If it is missing or incorrect, Google Cloud cannot map the SWA JWT subject to a Google Cloud principal and the token exchange fails.

In the Google Cloud Console, go to IAM & Admin > Workload Identity Federation. Open your OIDC provider and confirm that the attribute mapping sets google.subject to assertion.sub.

Issuer URI not updated after migration

If you migrate to a different SWA trust domain or Secrets Manager tenant, update the issuer URI on the OIDC provider.

 	
gcloud iam workload-identity-pools providers update-oidc swa-provider \
  --location=global \
  --workload-identity-pool=swa-pool \
  --issuer-uri="https://your-new-oidc-url.example.com"
Audience mismatch error

If authentication fails with "The audience in ID Token does not match the expected audience", update the allowed audiences on the OIDC provider.

 	
gcloud iam workload-identity-pools providers update-oidc swa-provider \
  --location=global \
  --workload-identity-pool=swa-pool \
  --allowed-audiences="https://iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/swa-pool/providers/swa-provider"
Project ID not detected by the Storage client

When a workload runs outside of Google Cloud environments, the Storage client cannot auto-detect the project. To avoid a "Project was not passed and could not be determined from the environment" error, pass the project parameter explicitly.

 	
client = storage.Client(project=project_number)
