 Panorama Support for Prisma Access 6.0 

 Prisma Access Addressed Issues 

 Where Can I Use This? What Do I Need? 

 Prisma Access (Managed by Panorama) 

 Prisma Access license 

 Minimum Required Prisma Access Version 6.0 Preferred or Innovation 

 The following topics describe issues that have been addressed in Prisma Access 6.0 
 and Prisma Access 6.0.1 . 

 Prisma Access 6.0.1 Addressed Issues 

 Issue ID Description 

 CYR-51157 Fixed an issue where Secure Inbound Access was not
 supported with Remote Networks—High Performance deployments.

 CYR-41740 Fixed an issue where, if there were more than 100
 connectors onboarded in the same region in a short duration of time,
 private app access through some of the ZTNA connectors might not
 work. 

 Prisma Access 6.0.0-h80 Addressed Issues 

 Issue ID Description 

 CYR-70786 Fixed an issue where, in multi-tenant Panorama,
 plugin validation fails upon bulk import operation of the remote
 network configuration. The issue occurred only when the remote
 network had secondary WAN configuration enabled. 

 CYR-69289 Fixed an issue where Prisma Access Multi-tenant
 customer Fast Session Delete feature enablement was not taking
 effect upon commit push. 

 CYR-52040 Fixed an issue where a Commit/Push from Panorama was
 triggered when the min_plugin version is not met (that is, with 5.2
 plugin), resulting in a "Panorama does not have an active internet
 connection" error. 

 Prisma Access 6.0.0-h75 Addressed Issues 

 Issue ID Description 

 CYR-63001 

 Effective May 29, 2026, PRA has been officially rebranded as
 Secure Agentless Access (SAA). This update introduces an
 expanded range of supported applications and a modernized user
 experience for both administrators and end users. 

 Key Changes and Enhancements 

 Modernized UI: The new user interface and updated navigation
 are now live directly in the Strata Cloud Manager (SCM)
 front end. 

 Panorama Integration: Panorama now features a cross-platform
 launch panel reflecting the new SAA identity. 

 Private Web Apps Support: You can now configure private
 web applications (HTTP/HTTPS) as a new application
 type. 

 Licensing Updates: Private Web Apps support is included with
 Prisma Access base licensing (ZTNA and Enterprise editions).
 Supporting RDP, SSH, and VNC application types still require
 the existing add-on license. 

 Prisma Access 6.0.0-h74 Addressed Issues 

 Issue ID Description 

 CYR-66709 Fixed an issue where the Export Remote Networks
 configuration did not work when the Remote Networks Template IKE
 Gateway was configured with a Peer IP Address Type as IP instead of
 Dynamic. 

 CYR-66504 Fixed an issue where failures were encountered (for
 example, the response was empty) when the CA certificate was being
 requested by Strata Logging Service. 

 CYR-66409 Fixed an issue where service connection onboarding
 might not display properly when the administrator creates a
 sub-tenant's name with the "remote-networks" keyword. 

 CYR-66277 Fixed an issue where, for Prisma Access Cloud Service
 plugin when IP optimization was enabled and IP Allowlist was
 enabled, there was a change and difference detected in the
 configuration between the cloud and the configuration, which pushed
 an empty change. Because of this action, any changes made by the
 administrator would be attributed to the __cloud_services user
 instead of the admin user that made the change. 

 CYR-63794 Fixed an issue where, if the Panorama license was
 renewed after its expiration, the cloud services OTP workflow and
 license capability fetch workflow did not complete without manually
 deleting the stale/expired license key files. 

 Prisma Access 6.0.0-h69 Addressed Issues 

 Issue ID Description 

 CYR-66281 Fixed an issue where SPNs were not appearing on the
 SD-WAN UI because of a Cloud Service Plugin issue. 

 CYR-64827 Fixed an issue to remove bad import for
 get_rn_to_ep_ip_list.py. 

 CYR-61262 Fixed a logging issue for commit validation on
 Panorama plugin to show the total number of Trusted Source IP
 Addresses instead of the total number of object entries. 

 CYR-52710 

 Fixed an issue with the PA 6.0.1 SBL "parking" feature, when an
 existing AggBw (Aggregate Bandwidth) tenant adds a Site-Based
 License (SBL), the back end "parks" both licenses together. This
 merges sites with
 bandwidth_cap and combines
 ip_sites_map with
 ip_bw_map within the
 inbound_access metadata. 

 The UI must continue to display all AggBw constructs and
 management options during this state. Since the data plane
 migration to RN-HP (Regional Next-Generation Hub) can take
 weeks, customers require uninterrupted access to their existing
 AggBw interface until the transition is complete.
