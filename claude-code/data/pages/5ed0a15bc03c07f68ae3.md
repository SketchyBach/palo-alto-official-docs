 Expand agent capabilities with MCP integrations 

 Connect Model Context Protocol (MCP) integrations in Cortex AgentiX to extend Agentic Assistant agents with third-party tools and external system access. 

 Cortex Agentic Assistant connects agents to external tools with Model Context Protocol (MCP) integrations. Agents use third-party MCP server tools to retrieve data and perform tasks in external systems. For example, an agent can open a Jira issue or check whether security scans are bypassed in GitHub workflows. 

 Cortex Agentic Assistant connects to external MCP servers through streamable HTTP. It supports OAuth-based and authless servers. The MCP server must be accessible through a URL. Install the relevant Cortex Marketplace content pack and configure an MCP integration instance. The integration discovers available tools and automatically generates agentic actions. 

 For agentic actions to be created from tools on an MCP server, the tools must have input and output descriptions on the MCP server. These descriptions are required for Cortex AgentiX to understand the tools' capabilities and the correct use cases. 

 Configure MCP integrations 

 To find MCP content packs, go to Settings → Marketplace . Under Types , filter for MCP . Examples include Cloudflare MCP , GitHub MCP , and Atlassian Cloud MCP . Use the Generic MCP content pack for MCP servers without a dedicated content pack. Each MCP integration includes required URL and authentication parameters. 

 You can create multiple integration instances for each MCP integration. For example, you might configure one instance of the GitHubMCP integration to connect to an environment with read tools and another instance to connect to an environment with both read and write tools. In addition, the GenericMCP integration can be used to connect to multiple MCP servers, each with a separate integration instance. 

 When you Test the integration instance, Cortex AgentiX verifies server connectivity. 

 If you are using OAuth-based authentication, the Test button returns an error containing the command to run in the playground in order to test the connection. 

 All configured MCP integration instances can be viewed in the Settings → Data Sources & Integrations page. You can view each integration instance and verify the status of the connection, Test the connection, enable or disable the integration instance, and view the last discovery timestamp. 

 Discover MCP tools and agentic actions 

 The integration instance checks hourly for new or changed third-party MCP server tools. Checks also run whenever you save an integration instance. Discovered tools are automatically registered as AI actions of type MCP Tool . Actions are created for each MCP integration instance. Multiple instances for the same MCP server create multiple actions for the same tools. Each action name includes the server, tool, and integration-instance names. Tool discovery creates system actions. You cannot edit these actions. You can enable or disable them. You can also mark actions as sensitive, requiring manual approval. By default, all MCP server actions are sensitive. 

 If an MCP tool is removed from the MCP server, the action will be unavailable due to missing content. If the tool is restored on the MCP server, the action is automatically re-enabled. 

 If you have a development and a production tenant, you can push actions created from MCP tools from development to production. 

 Add MCP tools to agents and manage permissions 

 Add MCP tool actions to custom agents in the Agentic Assistant Hub . By default, all users with custom agent access can use its available tools. To restrict MCP tool access, go to Settings → Configurations → Data Collection → Integration Permissions . Restrict MCP integration instance commands to one or more roles. Only users in permitted roles can use restricted actions.
