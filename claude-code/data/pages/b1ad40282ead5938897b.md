# Agent Sabotage

Agent Sabotage

Severity

🟡 Medium (6)

Short Description

Flags AI extensions that consume a large amount of tokens without a relevant reason, or that otherwise make the agent work less efficiently, wasting budget and derailing legitimate work.

Suggestion

Compare the component's resource consumption against its usefulness. Treat deliberate context pollution, capability denial, or output degradation as malicious rather than merely inefficient, and remove the component.

Information

Agent sabotage covers components built to degrade the agent rather than to attack the host. The techniques vary: padding the context window with irrelevant content so useful information is pushed out, instructing the agent to refuse or avoid capabilities it would normally use, forcing redundant work, or steering output quality downward.

The damage is real but indirect. There is no exfiltration and no code execution, so conventional security controls see nothing wrong; what the organization loses is token budget, engineering time, and trust in the agent's output. Distinguishing sabotage from poor engineering comes down to whether the pattern looks deliberate — a verbose but well-meaning skill wastes tokens, while one that injects large volumes of irrelevant text on every invocation is doing something else.

Risks

Budget drain: Unnecessary token consumption raises cost with no corresponding value.

Context pollution: Filling the context window crowds out the information the agent needs, degrading answers on unrelated tasks.

Capability denial: Instructions that discourage the agent from using tools or approaches reduce what it can accomplish.

Output degradation: Subtly worse code, analysis, or summaries erode trust and can introduce defects downstream.

Recommended Actions

Investigate the component

Read the evidence to see the specific sabotage pattern and where it appears.

Compare token usage on sessions with and without the component enabled.

Check whether the behavior is a deliberate pattern or an unintentionally verbose implementation.

Contain and remediate

Disable the component and confirm that agent efficiency and output quality recover.

Review other components from the same publisher for the same pattern.

Remove the component if the behavior is deliberate; report it to the marketplace.
