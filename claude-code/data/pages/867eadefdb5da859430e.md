 The following table details the changes in default behavior for Prisma Access 
 version 6.2. 

 Component Change 

 Remapped Ukraine Location 

 To better optimize the performance of Prisma Access, the
 Ukraine location is remapped from the Germany Central to
 the Poland compute location. 

 New deployments have the new remapping applied automatically. If you
 have an existing Prisma Access deployment that uses one of these
 locations and you want to take advantage of the remapped compute
 location, follow the procedure to add a new compute location to a
 deployed Prisma Access location. 

 The following table details the changes in default behavior for Prisma Access 
 version 6.20-h2. 

 Component Change 

 Internal Host Detection 

 During MU onboarding, the Internal Host
 Detection value is now strictly mapped to the DEFAULT
 Agent Settings profile in the portal. 

 Strict Mapping: The IHD value will only copy to the
 DEFAULT named Agent Settings profile. It will no longer
 automatically fall back to the first or top-most Agent
 Settings profile if DEFAULT is absent. 

 No Profile Fallback: If a DEFAULT Agent Settings profile
 does not exist in the portal, the IHD value will not be
 applied to any alternative Agent Settings profiles. 

 Admin Control: Administrators retain full flexibility to
 manually update or modify the IHD value directly within
 the DEFAULT portal Agent Settings at any time. 

 If you delete the internal host detection
 configuration from the Default settings, make sure that you
 remove the internal host detection configuration here as
 well.
