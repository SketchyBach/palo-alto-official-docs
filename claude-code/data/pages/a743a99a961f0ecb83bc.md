 Create jobs to process indicators example 

 Create jobs that process indicators and send them to a SIEM in Cortex XSOAR 8.14 On-prem. 

 In this example, when indicators are fetched from a threat intel feed, a job triggers a playbook to enrich the indicators to determine which indicators should be investigated. A time triggered job then pushes the relevant indicators to your SIEM.

 Content item 

 Description 

 Unit 42 Feed integration 

 Ingest indicators from Palo Alto Networks Unit 42 research team. 

 TIM - Process Indicators - Manual Review playbook 

 This playbook tags indicators ingested by feeds that require manual approval. To enable this playbook, the indicator query needs to be configured. The playbook uses the Indicator Auto Processing sub-playbook, which identifies indicators that should not be added to a blocked list, such as IP indicators that belong to business partners or important hashes. 

 For the TIM - Process Indicators - Manual Review playbook to run, it needs to be triggered by a job. The job concludes by creating a new incident that includes all the indicators that the analyst must review. 

 TIM - Add All Indicators Types to SIEM playbook 

 This playbook sends to the SIEM only indicators (IP, bad hash, domains, and URLs) that have been processed and tagged accordingly after an automatic or manual review process. 

 By default, the playbook is configured to work with ArcSight and QRadar, but change this to match the SIEM in your system. 

 Task 1. Configure the Unit 42 Feed to ingest indicators 

 If you have a TIM license, this feed is preconfigured. 

 Go to Settings & Info → Settings → Integrations → Instance and search for Unit 42 Feed . 

 Go to Settings → Configurations → Data Collection → Automation & Feed Integrations and search for Unit 42 Feed . 

 Click Add instance . 

 In the Collect section, select Fetches indicators . 

 Test the Feed to ensure that it is working correctly. 

 Save and Exit. 

 Task 2. Create a list of indicators to exclude 

 Before customizing the playbook, we recommend creating a list of indicators that you want to exclude from the manual review process. In this example, we will create a list of business partner IP addresses. 

 Select Settings & Info → Settings → Advanced → Lists → Add a List . 

 Enter a meaningful name for the list. For example, BusinessPartnersIPaddresses. 

 In the Content Type field, select Text . 

 Select who can view or edit the list in the PERMISSIONS section. 

 In the list enter a comma-separated list of IP addresses of your business partners. 

 Save the list. 

 Task 3. Customize the TIM - Process Indicators - Manual Review playbook to process the indicators 

 Go to Playbooks and search for TIM - Process Indicators - Manual Review and either detach or duplicate the playbook. 

 Note 

 If you detach a playbook, it does not receive content pack updates until it is reattached, but then your changes are discarded. Duplicate the playbook if you want to receive content pack updates and keep your changes. 

 Go to Incident Response → Playbooks and search for TIM - Process Indicators - Manual Review and either detach or duplicate the playbook. 

 Note 

 If you detach a playbook, it does not receive content pack updates until it is reattached, but then your changes are discarded. Duplicate the playbook if you want to receive content pack updates and keep your changes. 

 Click the Playbook Triggered task at the top of the playbook. 

 Change From Context data → Inputs → General (Inputs group) → OpenIncidentToReviewIndicatorsManually the value to Yes , so an incident with the indicators for review is created. 

 Select the From indicators radio button. 

 Under Query , enter a query to process the specific indicators that you want. For example, sourceBrands:"Unit42Feed" . 

 Save the task and then save the playbook. 

 Update the TIM - Indicator Auto Processing sub-playbook and either detach or duplicate the playbook. 

 To exclude business partner IP addresses that you defined in Task 2, locate and edit the TIM - Process Indicators Against Business Partners IP List task. 

 From the Inputs tab, under BusinessPartnersIPListName , select the source, and under LISTS , add the created list. 

 Save the task. 

 Save the playbook. 

 Task 4. Define a job to trigger the playbook when indicators are fetched 

 Go to Jobs → New Job → Triggered by delta in feed . 

 Go to Incident Response → Jobs → New Job → Triggered by delta in feed . 

 From the TRIGGERS section, select Specific feeds and add the feed configured in Task 1. 

 Add the name of the job. 

 In the Playbook field, add the playbook customized in Task 3. 

 Create the job. 

 Whenever indicators are ingested from Unit 42, the playbook runs and creates an incident if an incident needs to be reviewed. You can track the status of the job in the table on the Jobs page. 

 You can now add indicators to a SIEM. 

 Task 5. Customize the TIM - Add All Indicators Types to SIEM playbook 

 Go to Playbooks and search for TIM - Add All Indicator Types to SIEM and either detach or duplicate the playbook. 

 Note 

 If you detach a playbook, it does not receive content pack updates until it is reattached, but then your changes are discarded. Duplicate the playbook if you want to receive content pack updates and keep your changes. 

 Click the Playbook Triggered task at the top of the playbook. 

 Select From indicators and set the query for the indicators to add. For example tags:approved_black, approved_white . 

 The purpose of the playbook is to send to the SIEM only indicators that have been processed and tagged accordingly after an automatic or manual review process. The playbook comes out-of-the-box with queries that you can update if required. 

 Save the playbook. 

 Ensure the playbook includes a task that closes the investigation once it is completed. 

 Task 6. Define a time triggered job to push the indicators to the SIEM 

 Select Jobs → New Job . 

 Select Time Triggered . 

 (Optional) Select Recurring and determine how often you want the job to run. For example, run once a day at midnight. 

 Enter a name for the job. 

 In the Playbook field, select the TIM - Add All Indicator Types To SIEM playbook to run. 

 Create new job . 

 Whenever an indicator is ingested that has a relevant tag such as approved_list , the job pushes that indicator to the SIEM. 

 Task 7. Test the workflow 

 Open the job that you created to process indicators from Task 3. 

 You can tag any indicator with the tags that you want to push. It does not have to be this job. 

 In the Work Plan , open the Create Process Indicators Manually incident task. 

 In the Outputs tab, copy the incident ID for the incident that was created. 

 Go to Incidents and search for the incident ID that was created. 

 Review the indicators and update the indicators with tags that you want to push to the SIEM. 

 When finished with the review, in the Work Plan , click the Manually review the incident task, select Yes , and Mark Completed . 

 Select the job you defined in Task 6 and click Run now . 

 Go to Indicators and run the query tags:SIEM . 

 This tag is appended to every indicator that has been processed and pushed to the SIEM.
