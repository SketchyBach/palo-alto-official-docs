 Customize Prisma Access Objects Names using CloudBlade Tag 

 Learn to customize Prisma Access objects names using CloudBlade tag
 information 

 Where Can I Use This? What Do I Need? 

 Supported CloudBlades: 

 Prisma Access for Networks (Managed by Panorama) 

 Prisma Access for Networks (Cloud Managed) 

 Prisma SD-WAN 

 Prisma Access 

 Supported Cloud Plugin Versions 

 Prisma Access for Networks (Managed by Panorama) CloudBlade versions 3.x.x and
 later 

 Prisma Access for Networks (Cloud Managed) CloudBlade versions 3.x.x and
 4.x.x 

 The names of the objects created by the Prisma Access CloudBlades can be
 managed through configurable tags applied to the site. Use the tag
 prisma_name:<custom_name> for a site, where the
 <custom name> added must follow the below conventions: 

 The allowed characters and numbers are [a-z], [A-Z], [0-9]. 

 Characters must not exceed 12 or be fewer than 3 characters. 

 Ensure no duplicate prisma_name is set across sites. 

 You can customize the prisma_name:<custom_name> tag only for
 newer site on-boardings. 

 The following are some examples of valid and invalid tags: 

 Valid Tags 

 prisma_name:site123 

 prisma_name:auckland123 

 prisma_name:123auckland 

 prisma_name:12auck3land 

 Invalid Tags 

 prisma_name:a 

 prisma_name:ab 

 prisma_name:a b 

 prisma_name:a b c 

 prisma_name:a_bc 

 prisma_name:a-bc 

 To configure a custom name, you need to add the tag
 prisma_name:<custom_name> to the site before adding
 the prisma_access tag. 

 If the prisma_name tag isn't added, the Cloudblade returns to using an encoded version of
 the siteID in the prisma access object names created on Prisma
 Access.
