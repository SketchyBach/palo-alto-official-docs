AI Agent Runtime Policy Templates

Adopt Koi out of the box runtime policies in one click

Policy Templates are out-of-the-box AI runtime policies, built by Koi's security team, that you can enable from the AI runtime policies page. Each template arrives prefilled with the actions it covers, mapped to a MITRE ATLAS tactic to help you learn why this templet is powerful and can help protect your organization. A template policy is a runtime policy that can be edited, scoped and deleted like any other policy.

Why does this matter?

Most organizations know they should harden their AI agents. Far fewer know where to start.

Writing a runtime policy from scratch requires answering tough questions upfront: Which actions are truly destructive? Which routine tasks risk disrupting developer workflows if blocked? Where do credentials actually live? and many more.

Our pre-built templates eliminate that research burden. Each template is mapped to a MITRE tactic and carefully calibrated to protect your system without disrupting your employees' daily work.

How It Works
Ask
Copy
AI runtime Policies → Templates → pick a template → review prefilled policy → impact check → Create policy

Open the library - Go to AI runtime and click Templates, next to Create policy.

Find a template - Filter by category, action, or High impact, or search by name. A template can belong to more than one category, so it appears under each.

Review the prefilled policy - Clicking a card opens the policy builder with the rules, action, and default scope already filled in. You can adjust the values, change the action, narrow the scope to an endpoint group or a specific AI agent.

Run the impact check - See how much real activity in your organization the policy would have matched over the last 30 days, so the productivity impact is visible before enforcement.

Create the policy - It appears in the policy list and behaves like any custom policy: monitored in Policy Hits, exclusions handled through the request flow, editable at any time.

Categories

Templates are grouped by the asset or behavior they protect:

Category
What it protects

Secrets & Credentials

Protect the credential files on the endpoint an AI agent could read and leak

Destructive actions

Data, files, systems and more that can be destroyed and sometimes cannot be restored

Cloud & infra

Cloud environments and the resources running in them

Code & repo

Repository contents, history, and what reaches your main branch

Remote access

The endpoint itself, against inbound access

Dynamic code execution

Anything that would let code run again later, or run unnoticed

AI agent extensions

The MCP tools and Skills an agent is allowed to use

A High impact label marks templates that address the highest-severity scenarios.

Best Practices

Start with High impact Block templates. They address the highest-severity scenarios.

Validate impact check before creating. A template with no matches in the last 30 days is safe to enforce immediately. A template with a lot of matches is worth rolling out to one endpoint group first and more gradually.

Use Ask where the action is legitimate but sensitive. Pushing code, elevating privileges and opening a database session are all real work. Blocking them creates friction that gets policies disabled; asking keeps a human in the loop without stopping anyone.

Roll out by endpoint group. Scope a template to a small group, watch Policy Hits for a week, then widen.

Review before enabling. Templates are editable. Open the policy details, adjust what does not fit your stack, and enable it once it reflects your environment.
