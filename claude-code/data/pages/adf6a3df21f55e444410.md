Binary executions

Monitor and govern all binaries execution across your organization

The Koi Binary execution view provides organizations with real-time visibility into every binary execution event across their endpoints.

Execution events view presents each execution as a separate log entry. Every time a user launches a binary file, a new event is created and displayed in the UI.

This allows security and IT teams to investigate execution activity at the event level, understand user behavior,Understand who executed a binary, on which device, and when and analyze enforcement decisions in context.

Coverage

The Binary events view includes all binary execution logs collected from macOS endpoints.

Each time a binary is launched on an endpoint, a new execution event is generated and presented in the UI.

The events are collected using Koi’s integration with Santa on macOS, which provides execution-level logging and enforcement decisions. 

To enable this capability requires configuring the Santa integration in your environment. Setup instructions and technical details can be found here.

You can learn more about Santa here.


 Binary events table fields
Field
Description

File name

The binary file name, extracted from the execution path, for example chrome_crashpad_handler.

Status

The execution Santa decision, for example Allowed or Blocked.

Reason

Explains why the binary was allowed or blocked, and which policy was applied.

Hostname

The device name where the execution occurred.

Is signed

Indicates whether the binary is code-signed, based on signing metadata in execution logs.

Platform

OS platform, currently macOS only.

Timestamp

Date and time when the execution event occurred.

User

User account that executed the binary.

Local user

The local user account that executed the binary.

Group

Device group, based on the organization’s endpoint grouping.

Path

The file system path from which the binary was executed.

SHA256

SHA-256 hash of the binary file, this is the unique identifier for each row.

Signing ID

The signing identifier of the specific application or software, covering all its versions (Example: EQHXZ8M8AV:com.google.Chrome is the signing  of Google chrome desktop).

Team ID

The unique identifier of the publisher that signed the binary(Example: EQHXZ8M8AV is the Team ID of Google).

Process ID

The identifier of the process that executed the binary.

Parent process name

Parent process that launched the binary

Parent process ID

The identifier of the parent process that launched the binary.

Signing Certificate Hash

Hash of the signing certificate
