# Dynamic Context

Dynamic Context

Severity

🟠 High (7)

Short Description

Flags plugin or hooks that execute dynamically generated or remotely fetched code at runtime instead of shipping it statically. Remotely controlled content can change between runs without any package update.

Suggestion

Treat this as a loss of reviewability. Anything you approved at install time may not be what runs tomorrow. Require the plugin to ship its logic statically, or remove it.

Information

A plugin or hook that fetches code at runtime — downloading a script and executing it, evaluating remote content, or dynamically importing a module from a URL — moves the decision about what runs from the package you reviewed to a server you do not control.

This breaks the assumption every other control depends on. Version pinning does not help, because the version is unchanged; package review does not help, because the reviewed artifact only contains the fetch. It also creates a clean path for staged attacks — a plugin can serve benign content during evaluation and malicious content afterward, or target specific organizations based on the requesting IP, with nothing about the installed package changing.

Risks

Unreviewable behavior: What executes is decided at runtime by a remote party, not by the package you approved.

Bypassed version pinning: Pinned versions provide no protection when the payload is fetched rather than shipped.

Staged or targeted delivery: The remote source can serve different content to different environments or at different times.

Third-party compromise: If the remote source is breached, every installation executing its content is compromised at once.

Recommended Actions

Investigate the component

Read the evidence to identify the remote sources and how the fetched content is executed.

Retrieve the current remote content and review what it actually does.

Check whether the remote source is controlled by the publisher or by a third party.

Contain and remediate

Disable the plugin or hook until the behavior is understood.

Block the remote sources at the network or proxy layer if the plugin must stay installed.

Prefer a version that ships its logic statically; if the publisher will not provide one, remove the plugin.

Watch for repeated fetches from the same host in agent activity logs.
