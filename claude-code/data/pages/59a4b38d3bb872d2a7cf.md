 Application Intelligence Enhancements for SaaS Security Inline 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 SaaS Security Inline has upgraded its core application intelligence engine, delivering greater granularity over app-specific activities in policy configuration and a more consistent application experience across the Palo Alto Networks platform. 

 Expanded List of Configurable App-Specific Activities 

 To provide greater policy precision, SaaS Security Inline has expanded the range of application activities available for configuration. While administrators previously configured policy recommendations around a core set of standard activities—such as Upload, Download, Share, and Delete—the configuration workflow now exposes a broader range of functional activities dynamically tailored to the capabilities of each individual SaaS application, giving your security team the precision to build more targeted policies.

This resolves naming discrepancies and makes it easier to identify and manage applications consistently across the platform. You may also notice minor adjustments to the SaaS Visibility Application Attributes and their labels, aligning with the conventions used across product areas. 

 Your existing tags, custom risk scores, and policy rule recommendations continue to function without any changes.

 Custom Dashboards Retirement and AI Canvas Migration 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 Custom Dashboards in Strata Cloud Manager are retired and replaced by AI Canvas, the AI-first data exploration platform that eliminates manual widget configuration through natural language queries and a curated library of pre-built security visualizations. Instead of selecting, configuring, and maintaining widgets one by one, you describe what you want to see in plain English and AI Canvas builds it. With a pre-built widget library covering the most critical Network Usage, App Usage, and Advanced Threat Prevention (ATP) use cases, you can populate a full security operations canvas immediately with no query writing required. Both Custom Dashboards and AI Canvas are included in your existing Strata Cloud Manager Pro subscription, so there is no licensing change. Custom Dashboards are permanently removed on July 31, 2026 — complete your migration before that date. 

 Because the two features run on different architectures, there is no automated migration script, so you will need to rebuild your dashboards in AI Canvas. To aid in the transition, every previously supported Network Usage and App Usage widget has been recreated as a pre-built widget in the AI Canvas library and is available immediately. For ATP data including Threat Overview, Host Generating Cloud-Detected C2 Traffic, and Hosts Targeted by Cloud-Detected Exploits, use the dedicated Threats experience within the Activity Insights interface. 

 A small number of legacy widgets and categories are not available in AI Canvas: the Applications Using Non-Standard Ports widget from App Usage and all Compliance Summary category widgets have been dropped, DNS Security widgets are replaced by the dedicated DNS Security dashboard (currently in Beta), WildFire® widgets have been dropped due to minimal usage, and the Incidents category is no longer active. DLP and Device Security availability will be confirmed once data source verification is complete. The complete widget migration guide maps every legacy widget to its replacement.

 Custom SAML Role Mapping for Third-Party Identity Provider Integration 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 You can now define the mapping between SAML attribute values and access policies directly within Strata Cloud Manager, eliminating the need to configure platform-specific accessPolicies attributes in your third-party identity provider. Previously, third-party identity provider administrators had to construct Strata Cloud Manager-specific attribute values using the exact role name and tenant service group (TSG) ID format (for example, superuser@prn:1234567890:::: ), which required detailed knowledge of Strata Cloud Manager's internal role names and TSG structure. 

 With Custom SAML Role Mapping, you map your existing SAML values—such as group names or department identifiers already present in your third-party identity provider—to the appropriate access policies in a one-time configuration within the Identity Federations UI. Initial support includes the standard SAML attributes used by SD-WAN: memberOf , groups , and strataCloudManagerRoles . 

 This enhancement provides: 

 Simplified third-party identity provider configuration —No need to create or maintain Strata Cloud Manager-specific attributes and role syntax in your third-party identity provider. Use your existing groups or roles as-is. 

 Centralized access management —Define and manage all role mappings from a single location within Strata Cloud Manager, rather than coordinating changes across both the third-party identity provider and Strata Cloud Manager. 

 Cross-product consistency —Use standard SAML attributes like groups to maintain consistent access control across multiple SaaS products simultaneously. 

 Reduced risk of misconfiguration —Eliminates the need for third-party identity provider administrators to manually construct access policy strings with exact role names and TSG IDs, lowering the chance of errors. 

 To get started, configure custom SAML role mapping in your Identity Federations settings.

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 Attackers are increasingly using AI to produce unique, polymorphic malware variants that evade traditional signature and hash-based defenses. For effective protection, every malware, even though unique, needs to be stopped inline in seconds, without impacting user experience. 

 Prisma Access Prisma® Access explicit proxy with Advanced WildFire blocks threats inline , before malware reaches a user's device. It leverages Advanced WildFire's Code Genome technology to create resilient fingerprints that capture malware's true intent, enabling rapid detection and prevention of large volumes of unique AI-generated malware. A low-latency cloud architecture provides inline prevention including patient zero infections without impacting user experience. Protection extends to malware across all common file types, including documents (PDF, Microsoft Office), scripts (PowerShell, JavaScript), executables, archives, and for file sizes up to 100MB. 

 To use this feature, enable Inline Cloud Analysis within the WildFire profile, applying it to a security policy, and enable Enable Advanced File Handling in explicit proxy Advanced Security settings.

 On-Demand Webhook Testing 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 When you configure a webhook for incident notifications, you cannot verify that your endpoint URL, authentication method, and payload handling function correctly until a real incident triggers delivery. This lack of visibility means misconfigurations often go undetected and cause missed alerts during critical security events. To address this, Strata Cloud Manager now allows you to send an on-demand test payload directly from your webhook configuration , providing immediate confirmation that your integration works before an actual incident occurs.

 You benefit from this capability when you onboard a new webhook endpoint, rotate authentication credentials, or migrate receivers to new infrastructure. Because Strata Cloud Manager tests your current configuration values before you save them, you can iterate rapidly and confirm correctness in a single workflow without generating unnecessary incident traffic.

 Severity Criteria for Incident Settings 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 Administrators who manage large deployments often need to apply different actions to incidents based on their urgency. Previously, custom incident settings in Strata Cloud Manager only allowed filtering by product, incident category, subcategory, and incident code, which required you to create separate settings for each code rather than grouping incidents by severity. You can now select one or more severity levels—Critical, High, Warning, or Informational—as a condition when you create or update a custom incident setting. 

 This capability lets you build targeted rules that prioritize high-severity incidents for immediate notification while suppressing lower-severity incidents that do not require urgent attention. You can combine severity with other conditions or use it independently, and contextual filtering in the UI narrows category and code options to match your selected severity levels. Existing custom incident settings that you created before this capability continue to function without modification. Strata Cloud Manager treats those settings as having a severity value of Any, meaning they match incidents of all severity levels. 

 You can start using severity-based filtering by creating a custom incident setting and selecting severity values in the updated workflow.

 Strata Cloud Manager to Panorama Configuration Synchronization 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 You can now synchronize configurations from Strata™ Cloud Manager to Panorama®, eliminating the need to manually duplicate complex configurations across disconnected environments. By linking Panorama to your cloud tenant, you can synchronize shared configuration snippets directly to your existing deployments. 

 The integration uses a three-phase workflow to ensure consistent configuration delivery: 

 Linking: You discover and connect your Panorama appliances to Strata Cloud Manager. 

 Publishing: Each snippet is published as a corresponding newly-created device group and template on Panorama. Unsupported elements, such as IPSec tunnels and virtual wires, are pruned during this process. 

 Pulling: After synchronization, Panorama records the resulting device group and template updates as actions performed by the plugin rather than a specific administrator. You then move the device group to your desired hierarchy location, assign the reference template to your template stack, commit the changes to Panorama, and push them to your firewalls. 

 This workflow lets you push configurations across hybrid architectures without interrupting established processes. Built-in safeguards protect operational reliability through automatic timeout detection and persistent crash recovery, ensuring that partial or incomplete configurations never reach your network devices. You can monitor the exact status of every synchronization job directly from the centralized interface to maintain complete visibility into the health of your deployments. You can also view snippet version snapshots and audit history. 

 For more information, see Configuration Synchronization Between Strata Cloud Manager and Panorama .

 Test Email Validation for Notification Profiles 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 When you configure email notification profiles, you cannot verify whether your email addresses and settings will successfully deliver messages until a real notification event occurs, which can result in missed alerts and production issues. The Test Email feature solves this problem by allowing you to send a test message to all configured recipients directly from the notification profile creation or editing workflow, giving you immediate confirmation that your email configuration is functional before you rely on it for critical alerts. 

 You can use this feature any time you create or modify an email notification profile to validate that each recipient address is reachable through your email provider. When you select the Test Email action, the system sends a test message to every configured address using the same delivery path as production notifications, then returns a per-recipient result indicating whether your email provider accepted or rejected the message. This ensures that common misconfigurations such as incorrect addresses, authentication failures, or connectivity issues are surfaced immediately rather than silently failing when a real security event triggers a notification.

 Virtual Wire Subinterfaces for Cloud Managed NGFWs 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 When you need to enforce distinct security policies for different networks or departments on the same physical connection, a standard virtual wire can limit your ability to separate the traffic. Strata Cloud Manager now supports virtual wire subinterfaces , allowing you to logically divide your physical ports and classify traffic into different security zones without assigning MAC or IP addresses to the interfaces. 

 You can classify this incoming traffic based on VLAN tags, or a combination of a VLAN tag and an IP classifier like a specific address, range, or subnet. This feature allows you to integrate a firewall into an existing network and enforce specific security policies for different segments of traffic while acting as a pass-through link. By configuring virtual wire subinterfaces, you avoid the need to redesign your network, reconfigure surrounding network devices, or introduce complex routing while still gaining granular policy control over your tagged traffic.

 WildFire Incident Integration with Unified Incidents Framework 

 Release Date: June 2026 
 | 
 Last Updated: June 2026 

 When WildFire® detects suspicious activity across your environment, you need a way to surface findings as incidents without overwhelming your operations team with noise. The integration with the Unified Incidents Framework solves this by allowing WildFire to publish informational incidents through a centralized pipeline while giving you granular control over which objects generate incidents. By default, Strata Cloud Manager suppresses WildFire incident codes to ensure your queue remains relevant until you explicitly raise alerts for specific resources. 

 You can configure custom settings on a per-incident-code basis to select the exact objects for incident generation and optionally attach a notification profile to alert your team through preferred channels. Keep in mind that manual uploads do not support notifications. If you previously configured notifications in the legacy portal, you must recreate these settings in Strata Cloud Manager, as they do not migrate. To prevent duplicate alerts, Strata Cloud Manager sends only one email notification if you configure the same device in both the legacy and new portals. 

 Because these incidents are informational, the integration minimizes manual overhead. WildFire automatically clears the alerts after a controlled time period, and Strata Cloud Manager clears the associated incidents accordingly. Incidents also include a hold time, resulting in a five-to-six-minute delay for the first notification of every new incident. 

 To ensure alerting remains targeted when you configure WildFire incident settings, you must specify exact objects rather than using wildcards. The integration coordinates between WildFire and the correlation engine to match incoming alerts to your custom or default settings, ensuring accurate incident generation and proper notification routing across your deployment.
