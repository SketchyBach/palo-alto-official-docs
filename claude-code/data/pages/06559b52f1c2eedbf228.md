# Create an AI agent access policy

Skip To Main Content
Our Products
Create an AI agent access policy

This topic describes how to create access policies that control which users and AI agents can run tools on registered MCP servers.

How it works

An AI agent access policy grants access only when the principal and resource in a request both match: a principal (a user/role or an AI agent) trying to use a resource (a tool on an MCP server).

Users and roles: the users or roles allowed to initiate a session

AI agents: the registered agents those users can operate through

MCP servers and tools: the specific tools, on specific MCP servers, that the agent is permitted to run

When you create and manage access policies, note the following:

Deny-by-default access - The system grants access only through the allow policies that you create, and denies any request that no policy allows.

Enforcement requirements - A policy applies only when the AI agent and MCP server are registered and enabled, and the user is identified.

Tool discovery - The system discovers the tools on an MCP server the first time an AI agent connects to it, so connect with the agent to make the tools available to add to a policy.

Before you begin

You have the Secure AI Admin role. Only Secure AI Admins can create and manage AI agents access policies.

The MCP servers you want to include in the policy are registered. For details, see Register MCP servers.

You don't need to enable an MCP server to add it to a policy. However, the server must be enabled before AI agents can use it through the policy.

The AI agents you want to include in the policy are registered. For details, see Secure AI agents access.

An AI agent doesn't need to be in enabled state to add it to a policy. However, the agent must be enabled before it can use MCP servers through the policy.

For more information, see View and manage AI agent access policies.

Step 1: Set general details

Go to Manage > Policies > AI agents access.

On the AI agents access policies page, click Create policy.

On the General details page, enter the following:

Field

	

Description




Policy name

	

Enter a unique name for the policy.




Description (optional)

	

Add a short description of the policy's purpose. Up to 200 characters.




Owners (optional)

	

Assign users or roles as policy owners.

Click Select owners.

Search for and select users or roles. You can filter by type (User or Role) and identity source.

Click Add owners.




Policy tags (optional)

	

Add key-value tags to help organize or filter policies. Click + Add to add additional tag pairs.

Click Next.

Step 2: Add MCP servers and tools

Add the MCP servers and tools that authorized users and AI agents can access through this policy.

Click + Add MCP servers.

In the Add MCP server window, select MCP servers from the list.

The list shows each MCP server's identifier, category, and tool availability. Tool availability shows the number of tools discovered on that server.

Tool availability reflects the tools discovered the first time an AI agent connects to that MCP server. If no agent has connected yet, the count shows as Not discovered yet and updates after the first successful connection.

Click Next.

In the Configure <MCP server name> window, select which tools to allow on the server.

Choose one of the following options:

Select specific tools (default) — Select individual tools from the list. Only the selected tools are allowed to run. Newly discovered tools are denied by default.

Allow all current and future tools — Enable the Allow all current and future tools toggle to grant access to all tools currently on the MCP server and any tools discovered in the future.

When this toggle is on, access to newly discovered tools is granted automatically without requiring a policy update.

Tools are discovered the first time an AI agent tries to connect to the MCP server. Until tools are discovered, the policy allows access to the entire MCP server. After tools are discovered, you can edit the policy to restrict access per tool.

Do one of the following:

Click Add and select another MCP server to add an additional MCP server to the policy.

Click Add to policy to save the configuration and return to the MCP servers and tools summary.

Review the MCP servers and tools summary. Each server shows its tool access setting: the number of allowed tools, or All current and future tools.

To edit or remove a server, click the row menu (...) next to the server and select Edit or Remove.

Click Next.

Step 3: Add AI agents

Select the AI agents through which users can access the configured tools.

Click + Add AI agents.

In the Select AI agents window, choose one of the following options:

Select specific agents (default) — Select one or more registered agents from the list. Only registered AI agents are shown.

Allow all current and future AI agents — Enable the Allow all current and future AI agents toggle to grant access to all currently registered agents and any agents registered in the future.

When this toggle is on, new AI agents are granted access automatically when they are registered, without requiring a policy update.

Click Add to policy.

Click Next.

Step 4: Add users and roles

Select the users and roles that are permitted to operate through the assigned AI agents and access the configured tools.

Click + Add users and roles.

In the Add users and roles window, search for and select the identities to include. Use the filters to narrow results:

Type — Filter by User or Role.

Source — Filter by identity source: Idira Cloud Directory, Okta, or Entra ID.

To include all users in the policy, select the Everyone role instead of adding users individually.

Click Add to policy.

Click Done to save the policy.

For the system to apply a policy when an AI agent runs a tool, both the AI agent and the MCP server must be enabled.

Each time an AI agent runs a tool, the system records the attempt in the audit log, including whether it succeeded or failed.
