# Koi MCP Server

Connect a compatible AI client to Koi and explore your inventory, policies, findings, endpoints, and other Koi data using natural language—with the same tenant access and permissions as your Koi API key.

The Koi MCP Server exposes the Koi External API as Model Context Protocol tools. Instead of writing REST calls, you connect a client such as Cursor or Claude, and it discovers the available tools and calls them for you.

### What You Can Do

Once connected, you can ask your AI client questions such as:

* "Which high-risk browser extensions are installed across my endpoints?"
* "Show me every endpoint that still has the blocked VS Code extension installed."
* "What findings does this npm package have, and what are the evidence?"
* "List all policies currently set to block, and how many items each one matches."
* "Create a remediation for this item and add it to the blocklist."

The MCP server is a thin layer over the External API v2 - anything the REST API can do, the MCP server can do, with the same tenant scoping and the same permissions.

### Setup Requirements

1. You need a Koi **API key**. Create one in **Settings > API Access** (see below). MCP uses the same key as the REST API.
2. Your MCP client must support **remote MCP servers over Streamable HTTP** with a custom `Authorization` header. Clients that only support local `stdio` servers need a bridge such as `mcp-remote`.
3. API keys are scoped to your **entire Koi tenant**, not to an individual user or a subset of endpoints. Treat a key as a full-access credential.

### Create an API Key

1. In the Koi platform, navigate to **Settings > API Access**.
2. Click **+ Create API key**.
3. Choose an **Expiration date** — `1 week`, `2 weeks`, `1 month`, or `1 year`.
4. Click **Create**.
5. Copy the key from the table using the copy button in the **API Key** column. Store it in your organization's secret manager.

**Important:** The key is a bearer token that grants full access to your tenant's Koi data. Do not commit it to source control or paste it into a shared client config that syncs to a repository.

### Connect Your MCP Client

The Koi MCP Server endpoint is:

```
<https://api.prod.koi.security/api/external/v2/mcp>
```

Authenticate with your API key as a bearer token:

```
Authorization: Bearer YOUR_API_KEY
```

#### Cursor

1. Open your MCP configuration file — `~/.cursor/mcp.json` for all projects, or `.cursor/mcp.json` inside a single project.
2. Add the Koi server:

   ```json
   {
     "mcpServers": {
       "koi": {
         "type": "http",
         "url": "<https://api.prod.koi.security/api/external/v2/mcp>",
         "headers": {
           "Authorization": "Bearer YOUR_API_KEY"
         }
       }
     }
   }
   ```
3. Restart Cursor and confirm the `koi` server appears as connected in **Settings > MCP**.

#### Claude Code

1. Register the server from your terminal:

   ```bash
   claude mcp add --transport http koi \
     <https://api.prod.koi.security/api/external/v2/mcp> \
     --header "Authorization: Bearer YOUR_API_KEY"
   ```
2. Run `/mcp` inside Claude Code to confirm the server is connected and the Koi tools are listed.

#### Other MCP Clients

Any client that supports remote MCP servers over Streamable HTTP can connect using the endpoint and bearer token above. Provide:

* **Transport** - Streamable HTTP (not SSE, not stdio)
* **URL** - `https://api.prod.koi.security/api/external/v2/mcp`
* **Header** - `Authorization: Bearer YOUR_API_KEY`

For clients that only support local stdio servers, wrap the endpoint with a bridge such as `mcp-remote`.

### Verify the Connection

List the available tools directly with `curl` to confirm your key and endpoint are correct:

```bash
curl -sS '<https://api.prod.koi.security/api/external/v2/mcp>' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

A successful response returns a JSON-RPC result containing the full tool list. A `401` means the key is missing, malformed, or expired.

### Available Tools

The server generates one tool per External API v2 operation. Tool names follow the pattern `resource_action`, for example `inventory_list-inventory`. Each tool's description and parameters come straight from the API reference, so the tool list always matches the documented REST surface.

| Area                  | What you can do                                                                                                                                                                                    | Example tools                                                                                                                                                                                                                      |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inventory             | List, search, and drill into discovered items; see which endpoints have an item installed; read an item's risk analysis, MCP server capabilities (local and remote), and AI model artifact details | `inventory_list-inventory`, `inventory_search-inventory`, `inventory_list-endpoints-for-item`, `inventory_get-item-analysis`, `inventory_get-mcp-components`, `inventory_get-remote-mcp-components`, `inventory_get-model-details` |
| Endpoints             | List managed endpoints, read a single endpoint's inventory, archive an endpoint                                                                                                                    | `devices_list-devices`, `devices_get-device-inventory`, `devices_archive-device`                                                                                                                                                   |
| Endpoint Groups       | Create groups and manage group membership                                                                                                                                                          | `groups_list-groups`, `groups_add-device-to-group`                                                                                                                                                                                 |
| Policies              | Create, update, and delete policies; list policies; manage allowlists and blocklists; enable or disable a policy                                                                                   | `policies_list-policies`, `policies_add-to-blocklist`, `policies_update-policy`, `policies_create-policy`, `policies_delete-policy`                                                                                                |
| AIDR Runtime Policies | Full CRUD on runtime and configuration                                                                                                                                                             | `hardening-policies-v2_list-policies`, `hardening-policies-v2_create-policy`                                                                                                                                                       |
| Findings              | List findings and customize how a finding contributes to risk                                                                                                                                      | `findings_list-findings`, `findings_customize-risk`                                                                                                                                                                                |
| Remediation           | Read, create, and dismiss remediations                                                                                                                                                             | `remediations_get-remediations`, `remediations_create-remediation`                                                                                                                                                                 |
| Requests              | List, approve, and reject end-user approval requests                                                                                                                                               | `approval-requests_list-approval-requests`, `approval-requests_approve-approval-request`                                                                                                                                           |
| Koidex                | Look up risk reports and search the Koi threat intelligence index                                                                                                                                  | `koidex_get-risk-report`, `koidex_search-items`                                                                                                                                                                                    |
| AIDR                  | List agent sessions and session events                                                                                                                                                             | `agent-activity-external_list-sessions`, `agent-activity-external_list-events`                                                                                                                                                     |
| Private Items         | List private items and read their details                                                                                                                                                          | `private-items-v2_list-private-items`, `private-items-v2_get-private-item-details`                                                                                                                                                 |
| Platform              | Alerts, audit log, reports, and user management                                                                                                                                                    | `alerts_list-alerts`, `auditlog_list-audit-logs`, `reports_create-report`, `users_get-users`                                                                                                                                       |

For the exact parameters and response shape of any tool, see the matching operation in the [Koi API reference](https://docs.koi.ai/api-reference).

#### Not Available Over MCP

File-upload operations are excluded from the MCP tool set, because MCP tool arguments are JSON and cannot carry a multipart body. **Uploading a private item** must be done through the REST API or the Koi platform UI. Everything else on the v2 surface is available.

### Security Considerations

{% hint style="warning" %}
The Koi MCP Server exposes **write** tools as well as read tools. A connected AI client can archive an endpoint, change policies, create remediations, approve requests, and manage users. Only connect clients you trust, and review the tool calls your client proposes before approving them.
{% endhint %}

* **Tenant scope** - a key grants access to all of your Koi data. There is no per-endpoint or per-view restriction on MCP tools.
* **Key rotation** - choose the shortest expiration that fits your use case, and delete keys you no longer use from **Settings > API Access**.
* **Audit** - actions taken through MCP appear in the Koi audit log, attributed to the user who created the API key.

### Rate Limits

The External API v2 is limited to **30 requests per minute** per customer, per endpoint path.

MCP protocol traffic — the calls your client makes to discover tools and negotiate the session — does **not** count against that limit. Each actual tool invocation does, because it maps to a v2 REST call behind the scenes. If a client makes many tool calls in a burst, expect `429` responses.

### Troubleshooting

| Symptom                             | Cause and fix                                                                                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `401 Unauthorized`                  | The API key is missing, malformed, or expired. Confirm the header is exactly `Authorization: Bearer YOUR_API_KEY`, and check the key still exists in **Settings > API Access**. |
| Server connects but no tools appear | The client is probably using SSE or stdio. The Koi MCP Server supports Streamable HTTP only - set the transport explicitly.                                                     |
| `429 Too Many Requests`             | Tool calls exceeded 30 requests per minute. Narrow your question so the client makes fewer calls, or add filters to reduce pagination.                                          |
| Client cannot add a remote server   | The client only supports local stdio servers. Use a bridge such as `mcp-remote`.                                                                                                |
| Upload tool is missing              | Expected — file uploads are not exposed over MCP. Use the REST API instead.                                                                                                     |
