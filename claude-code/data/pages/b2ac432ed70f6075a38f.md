 GlobalProtect 6.1.14 (6.1.14-c32) Addressed Issues (Android) 

 The following table lists the issues addressed in GlobalProtect app 6.1.14
 (6.1.14-c32) for Android. 

 Issue ID 

 Description 

 GPC-25837 

 Fixed an issue where the GlobalProtect app versions 6.1.11 and
 6.1.12 crashed on Chromebook devices after successful Identity
 Provider (IdP) authentication, specifically when the SAML
 assertion was being sent to the firewall, preventing users from
 establishing a connection. 

 GPC-25634 

 Fixed an issue where the GlobalProtect Android app version 6.1.11
 crashed when MDM app restrictions did not include the
 `fips-induce-error` key. 

 GPC-26547 

 (GlobalProtect Chromebook users connecting to a gateway behind a
 Network Load Balancer (NLB) only) Fixed an issue where you could
 not send Host Information Profile (HIP) reports to the gateway.
 This occurred after you upgraded the GlobalProtect agent to
 version 6.1.13-24, specifically when connecting to a gateway
 behind an NLB. With this fix, you can now successfully send HIP
 reports. 

 GlobalProtect 6.1.13 Addressed Issues (iOS) 

 The following table lists the issues addressed in GlobalProtect app 6.1.13 for
 iOS 

 Issue ID 

 Description 

 GPC-25734 

 Fixed an issue where GlobalProtect Client 6.1.11 on iOS devices
 would randomly disconnect and require users to re-authenticate,
 despite a configured session lifetime. This occurred because
 OpenSSL had duplicate and conflicting code paths for iOS entropy
 gathering, along with a legacy custom mechanism for overriding
 random device paths, which led to unexpected GlobalProtect
 service restarts. 

 GPC-25817 

 Fixed an issue where GlobalProtect client versions 6.1.10 and
 6.1.11 on iOS devices experienced frequent and unexpected
 disconnections due to an SSL_CTX_new() failure caused by an
 error retrieving entropy.

 GPC-23778 

 Fixed an issue where GlobalProtect app installed on Android
 devices intermittently failed to send HIP reports when the
 device was in doze mode, resulting in the firewall removing the
 IP mapping for the user. 

 GPC-23965 

 Fixed an issue where Android devices running the GlobalProtect
 client in FIPS mode were unable to verify client certificates
 using OCSP (Online Certificate Status Protocol), leading to
 authentication failures. 

 GPC-24117 

 Fixed an issue where Chromebooks intermittently failed to
 authenticate to the Prisma Access Portal when using SAML
 authentication. This occurred because the ACS URL would briefly
 open in the default browser and then immediately disappear,
 leading to an "authentication failed" message and an exception
 in the GlobalProtect logs. 

 GPC-24228 

 Fixed an issue where Android devices running the GlobalProtect
 agent were unable to connect to gateways, displaying a "Could
 not verify the server certificate of the gateway" error. This
 occurred because a common code change caused the GlobalProtect
 agent to use the OpenSSL framework for gateway server
 certificate handshakes, which was unable to access certificates
 stored in the Android key-store. 

 GPC-24937 

 Fixed an issue where Android mobile device users of the
 GlobalProtect VPN client were unable to complete SAML
 authentication, as they were redirected to a blank page after
 attempting to connect. This issue occurred regardless of whether
 the embedded or default browser was used for SAML
 authentication. 

 GPC-24185 

 Fixed an issue where Chromebook users on GlobalProtect client
 version 6.1.9 could not connect to GlobalProtect gateways
 outside their geographical region. This occurred because when
 users attempted to switch gateways, a brief VPN disconnection
 due to higher network latency was misinterpreted by Android's
 Callback as a network loss. This triggered an unintended
 reconnection flow, prompting users for credentials and
 restarting the entire connection process (pre-login, login,
 network discovery), which resulted in the client connecting to
 the best available gateway instead of the user-selected
 gateway. 

 GPC-24053 

 Fixed an issue where GlobalProtect clients were unable to switch
 their connection to a different GlobalProtect gateway, even when
 the desired gateway was visible and manually selected, causing
 clients to remain connected to their default gateway.
