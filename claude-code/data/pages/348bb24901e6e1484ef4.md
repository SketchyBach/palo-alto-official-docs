 Migrate from Cortex XSOAR 6 to Cortex XSOAR 8 SaaS using the pre-migration and migration wizard 

 Step 4. Select whether to resync data and set the switchover date 

 Now that you have completed the UAT tests, you can do one of the following: 

 Resync data and set the switchover date 

 Decide not to resync data and complete the switchover immediately 

 You have up to 60 days from the date of the initial data sync to complete the migration process. 

 Important 

 If you exceed 60 days, you will no longer have access to the Cortex XSOAR 8 tenant. To recreate the tenant, you must open a support ticket in the Customer Support Portal (CSP), but all content changes will be lost. 

 When migration has finished, the Cortex XSOAR 8 tenant becomes available for end-users. Cortex XSOAR 6 is available for audit purposes, and you can't run any automations. 

 Note 

 If you are running a playbook communication task in Cortex XSOAR 6 that was not completed at the switchover date when clicking the task on Cortex XSOAR 8, you will be directed to Cortex XSOAR 6 and not to Cortex XSOAR 8. 

 Data resync and switchover 

 If you decide to resync data, at the switchover date, the following data from Cortex XSOAR 6 is resynced to Cortex XSOAR 8, and any changes to Cortex XSOAR 8 data are overwritten. 

 Items 

 Resync action at switchover 

 Content 

 In the migration wizard, you can select whether to resync content, which overwrites: 

 Playbooks 

 Scripts 

 Incident fields, layouts, and types 

 Indicator fields, layouts, and types 

 Lists 

 Note 

 If you decide to resync content data, all content you have created in Cortex XSOAR 8 is overwritten at the switchover date. If you want to keep custom content created in Cortex XSOAR 8, export the content as a backup before the resync. To export custom content in Cortex XSOAR 8, go to Settings & Info → Settings → Server Settings and Export all custom content . 

 Incidents and indicators 

 All indicator data is automatically resynced. 

 All incidents, including investigation data, created up to three months before the UAT phase, are resynced. For example, if the UAT period started on January 1st and the switchover date is set for March 1st, incident data from October 1st through March 1st is resynced. 

 Attachments 

 Note 

 Any changes made to incidents and indicators in Cortex XSOAR 8 are overwritten. 

 Regardless of whether you selected to migrate incidents and indicators, any incidents or indicators created on Cortex XSOAR 8 during the UAT are removed at the switchover date 

 Integrations and instances 

 In the migration wizard, you can compare the differences between integration instances in Cortex XSOAR 6 and 8 and select the instances you want to resync and overwrite. 

 At the switchover date, the fetch setting mirrors the setting in Cortex XSOAR 6 for incidents that fetch incidents or indicators. For example, if an integration's fetch incidents setting was enabled in Cortex XSOAR it is enabled on Cortex XSOAR 8 when the instance becomes active. 

 If using the REST Core API integration, we recommend you set this up during the UAT phase and not resync it. If you select resync and overwrite content, you should run further tests after the switchover date. For more information about testing this integration during the UAT phase, see REST Core API integration. 

 Any changes to the listening port for long-running integration instances are not overwritten. 

 Jobs 

 New jobs created in Cortex XSOAR 8 that did not exist in Cortex XSOAR 6, remain unchanged. Edited jobs created in Cortex XSOAR 8 will be overridden. 

 Users 

 Activate all users 

 Engines 

 Engine data, including Docker images. 

 Other data 

 Audit logs are automatically resynced and merged with existing audit logs in Cortex XSOAR 8. 

 Machine learning models are synced from Cortex XSOAR 6, but models created in Cortex XSOAR 8 are not overwritten. 

 Set the switchover date 

 At the switchover date, data is migrated (resynced) from Cortex XSOAR 6 to Cortex XSOAR 8. To minimize the expected downtime at the switchover date, we recommend setting the switchover date as soon as possible to shorten the UAT period and the accumulation of changes in Cortex XSOAR 6 that will occur during this time. 

 After setting the switchover date, you should receive an email confirming the migration date. 

 Note 

 The switchover starts on the selected date between 08:00 and 10.00 UTC. 

 Both Cortex XSOAR 6 and Cortex XSOAR 8 instances are temporarily unavailable as system settings and data are synchronized during the switchover date. 

 Switchover without data resync 

 You can decide not to resync data, which means there is no downtime at switchover. Cortex XSOAR continues to be available after switchover (until the end of your license). Your current Cortex XSOAR 8 tenant does not change, and any data created during the UAT period remains. 

 If you select not to resync data, you don't need to select a switchover date. In the migration wizard, click Start Switchover , and the switchover is immediate. 

 Rollback 

 You have up to 30 days to roll back the migration process. Go to the CSP and create a ticket requesting a rollback.
