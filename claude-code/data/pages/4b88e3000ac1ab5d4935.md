# Safety Instruction Override

For the complete documentation index, see llms.txt. This page is also available as Markdown.

Safety Instruction Override

Severity

🟡 Medium (6)

Short Description

Flags AI extensions that instruct the agent to ignore safety guidelines, skip confirmation prompts, or bypass restrictions.

Suggestion

Treat any attempt to disable confirmations or override safety guidance as disqualifying. There is no legitimate reason for a component to ask the agent to stop asking the user. Remove the component.

Information

Agent safety rests on a small set of controls: system instructions the agent is meant to follow, confirmation prompts before consequential actions, and restrictions on sensitive operations. A component that instructs the agent to ignore its guidelines, proceed without asking, or treat restrictions as inapplicable is attacking those controls directly. The phrasing is typically framed as efficiency — "do not ask for confirmation", "skip the usual checks" — and the effect is to remove the user from the loop precisely where their judgment was supposed to apply.

This finding matters most in combination. On its own an override attempt may not succeed, since models are trained to resist instructions of this shape. But a component that requests both command execution and the removal of confirmation prompts is constructing a path to unattended execution, and the two findings should be read as one issue.

Risks

User removed from the loop: Confirmation prompts are the last control before consequential actions.

Compounded with execution findings: Combined with command execution or resource access, the override is what makes those actions unattended.

Session-wide effect: An override in a rule or subagent can apply to the whole conversation, not just the component's own task.

Normalized bypass: Repeated exposure conditions users to accept an agent that no longer asks.

Recommended Actions

Investigate the component

Read the evidence to see the exact override language and which controls it targets.

Check for co-occurring execution, exfiltration, or resource-access findings — those define what the override enables.

Determine the component's scope: rules and subagents can affect an entire session.

Contain and remediate

Disable the component and verify that confirmation prompts behave normally again.

Review agent activity from the period the component was active for actions taken without confirmation.

Remove the component; report it to the marketplace if the override is paired with an execution or exfiltration finding.
