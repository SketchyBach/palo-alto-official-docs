Instruction Vulnerable to Prompt Injection

Severity

🟡 Medium (6)

Short Description

Flags AI extensions that are susceptible to prompt injection from the external inputs they read, letting untrusted content steer the agent.

Suggestion

This is a vulnerability, not malicious intent - the component is usually written in good faith. Assess it by what an attacker could reach through it: which untrusted sources it reads, and what the agent can do afterward. Prefer a version that separates untrusted content from instructions.

Information

Prompt injection happens when content the agent reads is treated as instructions rather than as data. A component is vulnerable when it pulls in external content - web pages, issue trackers, pull request descriptions, log files, API responses, user-supplied files - and passes it into the agent's context without marking it as untrusted.

The exploit path is straightforward. An attacker plants instructions in content the component will read: a comment on a public issue, a line in a log file, text on a web page. When the component feeds that content to the agent, the agent may follow the planted instructions with the same authority as the user's own request - including using tools the user has already approved.

Unlike most findings here, this one usually reflects a design oversight rather than intent. The publisher wanted the agent to summarize a web page; they did not intend to give whoever controls that page a channel into the agent. The severity comes from reachability: the more public the input source and the more capable the agent, the wider the exposure.

Risks

Attacker-controlled agent behavior: Planted instructions can redirect the agent mid-task.

Approved-tool abuse: Injected instructions inherit the tool permissions the user already granted.

Public reachability: Web pages, public issues, and shared documents let an attacker plant content without any access to your environment.

Chained impact: Combined with resource access or exfiltration findings, injection becomes a route to data theft.

Recommended Actions

Investigate the component

Read the evidence to identify which external inputs are read and how they enter the agent's context.

Assess reachability: can an attacker place content in those sources without access to your environment?

Check what the agent could do if steered — review co-occurring execution, resource access, and exfiltration findings.

Contain and remediate

Limit the component to trusted input sources where the configuration allows it.

Keep confirmation prompts enabled so injected instructions cannot silently trigger tool use.

Ask the publisher for a version that delimits untrusted content and instructs the agent to treat it as data.

Remove the component if it reads publicly writable sources and the agent has broad tool permissions.
