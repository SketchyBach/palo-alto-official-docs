# Out of Scope Component

For the complete documentation index, see llms.txt. This page is also available as Markdown.

Out of Scope Component

Severity

🟡 Medium (5)

Short Description

Flags plugins that have components that are not related to the plugin's stated purpose.

Suggestion

Compare the plugin's bundled components against its manifest description. Unrelated skills, hooks, MCP servers, or files may be leftovers, bundled extras, or something deliberately hidden inside a plugin installed for a different reason.

Information

A plugin declares its purpose in its manifest, and users install it based on that declaration. This finding compares the components actually bundled — skills, hooks, rules, commands, subagents, MCP servers, and files — against that declared scope, and flags the ones that do not belong.

There are innocent explanations — plugins accumulate components over time, and vendors ship several capabilities under a single package. The reason to look is that a plugin is a single approval decision covering everything inside it: a user who approves a plugin for its stated purpose implicitly approves every component it carries, including ones they never saw. Bundling unrelated components inside an otherwise legitimate plugin is a straightforward way to get capability installed under cover of something a user actually wanted.

Risks

Unreviewed capability: Components outside the stated purpose are installed without ever being independently evaluated.

Approval by association: A single install decision grants trust to every bundled component.

Hidden payload: An unrelated hook or MCP server can be the actual objective of an otherwise useful plugin.

Expanded attack surface: Every extra component adds capability that must be secured and maintained.

Recommended Actions

Investigate the component

Read the evidence to see which components were flagged and why they fall outside the stated scope.

Review each flagged component on its own — check for execution, exfiltration, or shadowing findings.

Check whether the publisher documents the extra components anywhere.

Contain and remediate

Disable the unrelated components individually if the plugin supports selective enablement.

Prefer a narrower plugin that provides only the capability you need.

Remove the plugin if an out-of-scope component carries findings of its own.
