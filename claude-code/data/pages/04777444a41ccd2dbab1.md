 Azure Manual Onboarding: Management group or tenant scope 

 Offboarding and resource decommissioning (optional) 

 To completely remove the Cortex deployment, you must execute the offboarding process sequentially across your Azure hierarchy. Deleting resources in this strict, bottom-up order prevents orphaned dependencies and lingering permissions. 

 Layer 1: Child subscription scope (run for each child subscription) 

 Ask Copy 

 az account set --subscription " <CHILD_SUBSCRIPTION_ID> " 

 # 1. Remove per-sub role assignments 
 for ROLE in " <ASSET_DISCOVERY_DATA_ROLE_NAME> " " <DSPM_DATA_ROLE_NAME> " " <AUTOMATION_DATA_ROLE_NAME> " " <KSPM_ROLE_NAME> " " Key Vault Crypto Service Encryption User " ; do 
 az role assignment delete --role "${ ROLE }" --assignee " <CORTEX_OBJECT_ID> " --scope " /subscriptions/<CHILD_SUBSCRIPTION_ID> " || true 
 done 

 # 2. Remove RG-scoped role assignments 
 for ROLE in " <DSPM_RG_ROLE_NAME> " " <ADS_RG_ROLE_NAME> " ; do 
 az role assignment delete --role "${ ROLE }" --assignee " <CORTEX_OBJECT_ID> " --scope " /subscriptions/<CHILD_SUBSCRIPTION_ID>/resourceGroups/<RG_NAME> " || true 
 done 

 # 3. Delete the per-sub cortex-platform-rg (kills the ADS gallery) 
 az group delete --name " <RG_NAME> " --yes --no-wait || true 

 Layer 2: Host subscription scope (run once) 

 Ask Copy 

 az account set --subscription " <HOST_SUBSCRIPTION_ID> " 

 # The host sub's cortex-platform-rg holds the EH namespace + EH + consumer 
 # group + UAMI + federated credentials + Storage Account. 
 az group delete --name " <RG_NAME> " --yes --no-wait
