 Migration Prerequisites for Cortex XSOAR 8 SaaS Multi-Tenant 

 Before you start the migration, review the migration prerequisites and other requirements for Cortex XSOAR 8 SaaS multi-tenant. 

 Before starting the migration, review the following prerequisites for the relevant Cortex XSOAR 8 SaaS multi-tenant migration process. 

 Self-Service Migration 

 Review the feature changes in Cortex XSOAR 8, including users and roles. For more information, see Cortex XSOAR 8 Feature Changes . 

 Plan your migration. Coordinate and obtain approval for the migration dates through your internal change management process. 

 Review the license and retention requirements for Cortex XSOAR 8 multi-tenant. 

 Upon migration and renewal, you receive the main tenant and one child tenant with your base multi-tenant license. You need to purchase additional licenses for your additional child tenants. For more information, see Understand Cortex XSOAR licenses . 

 By default, Cortex XSOAR keeps incidents per tenant for six months. You can purchase incident retention licenses to extend the incident retention of one or more child tenants. These licenses, once purchased, are available for allocation to child tenants in the Cortex Gateway. For more information, see Data Retention Policy .

 Users and roles 

 Review the users and roles feature in Cortex XSOAR 8. A unique email address is required for users to access the Cortex XSOAR 8 tenants. In your Cortex XSOAR 6 multi-tenant deployment, verify that all local users that need to be migrated, including the default admin, have a unique email address. For more information, see Set up Users and Roles . 

 Important 

 Use a valid email address so that users can receive their activation notification. This email address is also used when they need to reset their password.

 Migration dates 

 Coordinate and obtain approval for the migration dates through your internal change management process. A brief period of downtime may be required when the migration is completed. 

 All child tenants must be switched over first, and then the main tenant. 

 Note 

 You have 60 days from the date of the initial data sync to complete the switchover for child tenants and 90 days for the development and the main tenants. 

 Cortex XSOAR 6 

 Version 

 Upgrade your Cortex XSOAR 6 instance to Cortex XSOAR 6.14 and above. 

 Incidents and indicators 

 If migrating incidents and indicators, ensure you have sufficient memory in Cortex XSOAR 6 (child and development tenants). 

 Note 

 Consult with your Customer Service team for system best practices and a health check, where necessary. 

 Diagnostic issues 

 In your Cortex XSOAR 6 multi-tenant deployment, fix any system diagnostic issues, which enables a faster initial data sync, a shorter downtime at the switchover, and a better performance on Cortex XSOAR 8. For more information about how to fix system diagnostic issues, see Fix System Diagnostics Issues . 

 Bolt/Elasticsearch specifications 

 On your child tenant/development tenants, ensure that you comply with the following recommended specifications: 

 Bolt deployments: See System Requirements . 

 Elasticsearch deployments: See Elasticsearch System Requirements . 

 Private remote repository 

 If using a private remote repository, verify that the remote repository branch is not protected before starting the migration process. You can set it to protected after the switchover (migration is complete). 

 Deprecated content 

 Update any deprecated content in your Cortex XSOAR 6 multi-tenant deployment to supported content. For example, in Cortex XSOAR 6, if you have configured the Demisto REST API integration, replace it with the Core REST API. When you start the migration process, the initial data sync includes the updated supported content to Cortex XSOAR 8. If you do not update before the initial data sync, the content is not migrated, and you must configure it in Cortex XSOAR 8. 

 Recommended Steps 

 Familiarize yourself with the Cortex Gateway. The Cortex Gateway is a central portal for managing your Cortex products. Although most settings can also be configured in the Cortex XSOAR 8 tenant, there are more options in the Cortex Gateway. You can manage users through the Customer Support Portal (CSP) or SSO. User management in the CSP applies to all Cortex products. For more information, see Set up Users and Roles 

 Understand the latest features and improvements by going to the Cortex XSOAR 8 Release Notes . 

 Update your firewall's allow list for Cortex XSOAR 8. For more information, see Cortex XSOAR 8 IP addresses .
