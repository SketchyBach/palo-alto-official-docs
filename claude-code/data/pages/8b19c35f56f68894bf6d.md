 Configure Your Cisco APIC to Secure East-West Traffic 

 Complete these steps to configure your Cisco APIC to secure east-west traffic with a
 Palo Alto Networks firewall. 

 Where Can I Use This? What Do I Need? 

 VM-Series firewall deployment in Cisco ACI 

 VM-Series plugin 

 Panorama 

 VM-Series licenses 

 Cisco ACI Fabric 

 Panorama plugin for Cisco ACI 

 Create a VLAN Pool and Domain 

 Configure the VLAN pool that will be used to allocate VLANs to the firewall when
 you attach interfaces to the ACI infrastructure for EPGs. The firewall’s VLAN
 pull should have a static VLAN range. 

 Configure a dedicated domain for the firewall. A domain for the firewall is
 required to map the VLANs to the EPGs. Create a physical domain for a physical
 firewall and create a VMM domain for a VM-Series firewall. 

 Create a VLAN pool: 

 Log in to your APIC. 

 Select Fabric Access Policies Pools VLAN . 

 Right-click VLAN and select
 Create VLAN Pool . 

 Enter a descriptive Name for your VLAN
 pool. 

 Select Dynamic Allocation for Allocation
 Mode. 

 Click the plus (+) button to the right of Encap
 Blocks . 

 Enter your VLAN range in the VLAN Range 
 field. 

 Select Static Allocation from the Allocation
 Mode drop-down and select OK . 

 Submit your changes. 

 ( Physical firewall only ) Create a physical domain: 

 Select Fabric Access Policies Physical and External Domains Physical Domains . 

 Right-click Physical Domain and select
 Create Physical Domain . 

 Enter a descriptive Name for your physical
 domain. 

 Select the VLAN pool you created in the previous procedure from the
 VLAN Pool list and Submit your changes. 

 ( VM-Series firewall only ) Create a VMM domain: 

 Select Virtual Networking VMM Domains VMware . 

 Right-click VMware and select
 Create vCenter Domain . 

 Enter a descriptive Name for your VMM
 domain. 

 Select VMware vSphere Distributed Switch 
 from the Virtual Switch drop-down. 

 Select VLAN from the
 Encapsulation drop-down. 

 Select your VLAN pool from the VLAN Pool 
 drop-down. 

 Click the plus (+) button to the right of vCenter
 Credentials . 

 Enter a descriptive Profile Name and your
 vCenter login information. 

 Click the plus (+) button to the right of
 vCenter . 

 Enter a descriptive Name . 

 Select vCenter from the Type drop-down. 

 Enter your vCenter IP address under
 IP/Hostname . 

 Select the vCenter Credentials profile you created from the
 Associated Credential drop-down. 

 Submit your changes. 

 Configure an Interface Policy for LLDP and LACP for East-West Traffic 

 LLDP is necessary for forwarding to work correctly in the ACI environment; ACI
 does not deploy a subnet router interface on a leaf switch unless it detects an
 endpoint on the switch that requires one. LLDP helps determine if a subnet
 router interface is required. 

 LACP provides greater resiliency and recovery speed on a link failure. 

 Create an LLDP Interface Policy: 

 Select Fabric Access Policies Interface Policies Policies LLDP Interface . 

 Right-click on LLDP Interface and select
 Create LLDP Interface Policy . 

 Enter a descriptive Name for your LLDP
 interface policy. 

 Select Enabled for Receive
 State . 

 Select Enabled for Transmit
 State . 

 Submit your changes. 

 Create a Port Channel policy to enable LACP: 

 Select Fabric Access Policies Interface Policies Policies Port Channel . 

 Right-click on Port Channel and select
 Create Port Channel Policy . 

 Enter a descriptive Name for your port
 channel policy. 

 Select LACP Active from the
 Mode drop-down. 

 Submit your changes. 

 Establish the Connection Between the Firewall and ACI Fabric 

 Attach your firewall to the leaf switch through a VPC connection using the
 Ethernet interface (or Aggregate Ethernet group) you configured on your firewall
 earlier in this procedure. Connect the interface or interfaces to the same ports
 on the leaf switches. 

 Select Fabric Access Policies Quick Start . 

 Select Configure an interface, PC, and VPC . 

 Click the green and white plus (+). 

 Select the leaf switch or switches to which your firewall is connected from
 the Switches drop-down. 

 Click the green and white plus (+). 

 Select VPC as the Interface Type . 

 In the Interfaces field, enter the number of the
 interface your firewall uses to connect to the leaf switch. 

 Enter a descriptive name into the Interface Selector
 Name field. 

 Select LLDP-Enabled from the LLDP
 Policy drop-down. 

 Select LACP Active from the Port Channel
 Policy drop-down. 

 Select Bare Metal for a physical firewall or
 ESX Hosts for the VM-Series from the
 Attached Device Type drop-down. 

 Select Choose One for
 Domain . 

 Select the physical domain or VMM domain you created previously in this
 procedure from the Domain drop-down. 

 Select Save . 

 Select Save and then
 Submit . 

 Repeat this procedure for the second firewall in your HA pair. 

 Create a VRF and Bridge Domain 

 A tenant requires a VRF for all bridge domains and subnets. In this example, you
 will create a single, common VRF for the firewalls and endpoints. Then configure
 a dedicated bridge domain for your firewall and disable dataplane learning to
 use Policy-Based Redirect in a bridge domain. 

 Create a VRF: 

 On the Tenants tab, double-click on the name
 of your tenant. 

 Select Networking VRFs . 

 Right-click VRFs and select
 Create VRF . 

 Enter a descriptive Name for your VRF. 

 Uncheck Create A Bridge Domain . 

 Select Finish . 

 Create a bridge domain for the firewall: 

 On the Tenants tab, double-click on the name
 of your tenant. 

 Select Networking Bridge Domains . 

 Right-click Bridge Domains and select
 Create Bridge Domain . 

 Enter a descriptive Name for your bridge
 domain. 

 Select the VRF you created in the previous procedure from the
 VRF drop-down and select
 Next . 

 Configure VM-Series Firewall as an L4-L7 Device 

 Define the firewall as an L4-L7 device in the APIC so ACI can insert it into the
 traffic flow. You configure L4-L7 devices in the APIC as a device cluster, which
 is a construct that represents a single firewall or a firewall HA pair acting as
 a single device. Device clusters have one or more logical interfaces, which
 define the path of the member firewalls with a VLAN from the physical domain.

 On the Tenants tab, double-click on the name of your
 tenant. 

 Select Services L4-L7 Devices . 

 Right-click Devices and select Create
 L4-L7 Device . 

 Clear the Managed check box. 

 Enter a descriptive Name for your L4-L7
 Device. 

 Select Firewall from the Service
 Type drop-down. 

 Select Physical for a physical firewall or
 Virtual for a VM-Series firewall from the
 Device Type drop-down. 

 Select the physical or VMM domain you created previously from the
 Domain drop-down. 

 Select HA Node for View . 

 Under Device 1 , click the plus (+) icon to the right
 of Device Interfaces . 

 Enter a descriptive Name for this interface. 

 Under Path , select the path to the primary firewall
 in your HA pair. 

 Click Update . 

 Under Device 2 , click the plus (+) icon to the right
 of Device Interfaces . 

 Enter a descriptive Name for this interface. 

 Under Path , select the path to the secondary
 firewall in your HA pair. 

 Click Update . 

 Under Cluster , click the plus (+) icon to the right
 of Cluster Interfaces . 

 Enter a descriptive Name for the cluster. 

 Select the two interfaces you configured above from the list under
 Concrete Interfaces . 

 The APIC requires that you configure two
 interfaces. However, because there is only one connection between the
 firewall and the ACI fabric, only one of the interfaces is used. 

 Under Encap , enter a VLAN from the static VLAN pool
 you created earlier. Traffic is redirected to the firewall on the VLAN that
 you assigned. 

 Select Update . 

 Select Finish . 

 Create a Policy-Based Redirect (PBR) 

 The policy-based redirect (PBR) leverages the MAC address of the interface on the
 firewall. Before configuring the PBR setting on the APIC, you must get the MAC
 address from the firewall. 

 Get the MAC address of the firewall: 

 Log in to the firewall CLI. 

 Use the command show interface all to
 display the MAC addresses of your configured interfaces. 

 Copy the MAC address of the interface that will receive the
 redirected traffic. 

 Create the L4-L7 policy-based redirect: 

 Log in to the APIC. 

 On the Tenants tab, double-click on the name
 of your tenant. 

 Select Policies Protocol L4-L7 Policy Based Redirect . 

 Right-click L4-L7 Policy Based Redirect and
 then select Create L4-L7 Policy Based
 Redirect . 

 Enter a descriptive Name for your Policy
 Based Redirect. 

 Click the plus (+) icon to the right of
 Destinations . 

 In the IP field, enter the IP address of the
 interface that will receive the redirected traffic. 

 In the MAC field, enter the MAC address that
 you copied from the firewall CLI. 

 Select OK . 

 Select Submit . 

 Create and Apply a Service Graph Template 

 This section helps you to create a service graph template that uses the device
 cluster representing the firewall in a policy-based redirect integration. Apply
 this service graph to Endpoint Groups (EPGs) to protect the traffic. A contract
 and contract filter rules define the traffic that can be forwarded to the
 firewall. 

 Create a service graph template: 

 On the Tenants tab, double-click on the name
 of your tenant. 

 Select Services L4-L7 L4-L7 Service Graph Templates . 

 Right-click L4-L7 Service Graph Template and
 select Create L4-L7 Service Graph Template .

 Enter a descriptive Graph Name for your
 service graph template. 

 Select Create a New One for Graph
 Type . 

 Click and drag the L4-L7 device you created in the previous
 procedure between the consumer and provider EPGs. 

 Select Routed for
 Firewall . 

 Select Routed Redirect . 

 Select Submit . 

 Apply the service graph template: 

 On the Tenants tab, double-click on the name
 of your tenant. 

 Select Services L4-L7 . 

 In the EPGs Information pane, select your
 consumer and provider EPGs from the Consumer
 EPG and Provider EPG 
 drop-downs. 

 Select Create a New Contract . 

 Enter a descriptive Contract Name . 

 Unselect No Filter (Allow All Traffic) .
 Using this option is not recommended. To allow all traffic between
 the EPGs to be redirected to the firewall, it is recommended that
 you create a filter to do this. 

 Click the plus (+) icon to the right of Filter
 Entries . 

 Create a rule (or rules) to define what traffic is allowed to pass
 between the EPGs and redirected to the firewall. 

 Select Next . 

 Select the service graph template you created in the previous
 procedure from the Service Graph Template 
 drop-down. 

 In the consumer and provider pane, select the bridge domain
 containing your firewall from the BD 
 drop-downs. 

 Select the policy-based redirect you created previously from the
 Redirect Policy drop-downs. 

 Select the cluster interface you created with you L4-L7 device from
 the Cluster Interface drop-downs.
